# KeyPort 文档导航

## 当前目标架构

以下文档定义 Issue [#26](https://github.com/jihtsan/key-port/issues/26) 后的目标方向，后续实现应优先以它们为准：

1. [领域词汇](../CONTEXT.md)：统一设备、远端资源、访问配置、SSH 身份、密钥授权和拓扑等概念。
2. [Graph 拓扑与跨设备授权架构](./Graph拓扑与跨设备授权架构.md)：定义 Graph 语义、数据模型、添加/授权流程和 iCloud 同步边界。
3. [整体重构与迁移计划](./整体重构与迁移计划.md)：定义 UI 全量替换、模块拆分、文件处置、V3 → V4 迁移和实施阶段。
4. [ADR 0001：Graph 是访问事实的投影](./adr/0001-graph-is-a-projection-of-access-facts.md)：记录 Graph 不作为授权事实源的决策。

## 当前实现与历史基线

以下文档仍用于理解现有 V3/MVP 的需求、安全约束和验证结果，但其中的列表式 UI、`ServerConnection` 聚合模型和单快照 CloudKit 同步不再代表目标架构：

- [SSH KeyPort 一期需求规格](./SSH-KeyPort-一期需求规格.md)
- [一期实现架构与验证说明](./一期实现架构与验证说明.md)
- [SSH 技术原型结论](./SSH-技术原型结论.md)
- [macOS 技术框架与组件选型](./macOS-技术框架与组件选型.md)

安全相关约束继续有效，包括 Host Key 先验证、密码只进入 Keychain、私钥不跨设备同步、远端授权写入幂等并复验，以及不覆盖未知 SSH 配置或公钥。

## 阅读顺序

- 想理解产品：先读领域词汇，再读 Graph 架构的第 1、4、5、6、7 节。
- 想开始开发：先读整体重构计划的第 4、5、7、8 节。
- 想检查安全边界：读 Graph 架构第 3、8、10 节，再对照 SSH 技术原型结论。
- 想了解当前代码：读一期实现架构与验证说明，并将其视为迁移输入而不是最终结构。
