- 状态：提案
- 文档版本：V2.1
- 日期：2026-08-28
- 关联 Issue：[GitHub #26](https://github.com/jihtsan/key-port/issues/26)
- 产品目标：[Graph 拓扑与跨设备授权架构](./Graph拓扑与跨设备授权架构.md)
- 技术基线：[主机工作台技术架构与迁移契约](./Design/JODER-10/host-workbench-architecture.md)

## 1. 改版决策

可以果断替换当前 UI，也应该删除已经固化旧信息架构的页面和集中式编排代码；但不应删除已经落地的 Host v6、SSH 安全、CloudKit v2、迁移、发现和隧道承重层。

重构策略是：

- **UI 全量替换**：Graph 成为默认工作区，Nodes 列表成为等价管理视图，旧“服务器/密钥/设备/日志”四块并列导航退出主结构。
- **Host v6 成为唯一目标领域图**：不新建 `RemoteResource/AccessProfile` V4，也不引入第二套 Graph 数据库。
- **应用编排重建**：把 3049 行 `AppModel` 中的接入、密钥授权、同步和任务状态提取成深模块。
- **已验证实现复用**：系统 OpenSSH、AskPass、Keychain、Host Key、SSH Config、Cloud v2、Host v6 mutation workflow、Tailscale 和 Tunnel 作为适配器继续使用。
- **先投影、再切写权、最后删除旧 UI**：Canary 阶段 Graph 只读；Host v6 authority 和新命令完备后再切换写路径。

这不是在现有侧边栏增加一个 Graph 标签页。最终状态只有一套领域事实和一套新 UI，旧页面与 V5 写路径只在迁移期间存在。

## 2. 当前实现评估

### 2.1 已有承重能力

以下代码是新架构的输入，不应随 UI 一起推倒：

- `HostV6.SyncedGraph` 已规范化 Host、Address、SSH Account、Device、Key、Pin、Service、Authorization 和 Node Association。
- V5 → V6 影子迁移、来源证明、authority manifest、checkpoint、journal 和 compatibility projection 已实现。
- CloudKit v2 已提供单向 V1 输入、向量时钟、墓碑、Merge Review、CAS 重试、payload allow-list 和 800 KiB 门禁。
- Host v6 mutation workflow 已提供命令幂等、revision 检查、删除/撤销语义和外部效果恢复。
- OpenSSH 路由、Trusted Session、Host Key、AskPass、Keychain、SSH Config 和远端 `authorized_keys` 安全更新已经形成明确边界。
- Saved Service、服务发现、直连/隧道决策、Broker 生命周期和精确清理已经具备领域与基础设施实现。
- `PasswordlessPrimaryAction` 已把用户入口收敛成验证、启用、生成密钥、输入密码和核对 Host Key。
- 自动测试已经覆盖 Host v6 图、Cloud v2、迁移、路由、服务、隧道和主动作策略。

### 2.2 需要替换的结构

| 当前现状 | 主要问题 | 目标处理 |
| --- | --- | --- |
| 默认 UI 仍读取 V5 `AppSnapshot`/compatibility snapshot | 用户看不到 Host v6 中地址、服务和授权关系的真实图 | Graph 直接投影 `MetadataEnvelope` |
| `AppModel.swift` 约 3049 行 | 导航、表单、SSH、Cloud、Tailscale、发现、迁移和任务状态集中 | 提取 Graph、Enrollment、Access、Sync 和 Activity 模块 |
| 四块侧边栏分别展示服务器、密钥、设备和日志 | 用户要跨页面拼装“哪台 Mac 能访问哪个 Host/Service” | Graph 默认回答关系，Inspector 汇总细节 |
| `ServerConnection` 兼容模型仍驱动新增和编辑 | Host v6 已有规范化实体，但创建/更新命令覆盖不足 | 补齐 Host v6 mutation commands，再切换表单写路径 |
| 免密动作虽有共享策略，但执行仍在 AppModel | UI 入口收敛，行为编排仍过深耦合 | 提取 `AccessCoordinator` |
| 新增、SSH Config 导入和 Tailscale 纳管路径不同 | Host Key、密码和保存事务体验不一致 | 统一 `EnrollmentCoordinator` |
| 单一 `isBusy` 控制大量不相关任务 | 不能表达并发、资源锁、逐项进度和恢复 | 改为有类型的 `OperationRun` 与资源范围 |
| Host v6 feature flags 和 authority 状态对普通用户不可见 | Graph 若误用影子图可能让用户以为已取得写权 | UI 明确显示 canary、authoritative、compatibility rollback |
| 当前 `DESIGN.md` 仍以旧四栏目为 Active IA | 后续 UI 容易继续在旧结构上局部修补 | 将其标为当前实现基线，新目标以本文为准 |

## 3. 目标 UI 信息架构

### 3.1 主窗口

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 添加 | 当前设备/全部设备/服务 | 搜索与过滤 | 同步/写权 | 当前任务    │
├──────────────┬───────────────────────────────────┬───────────────────┤
│ Sidebar      │ Graph Canvas / Nodes List         │ Inspector         │
│              │                                   │                   │
│ Graph        │ Device、Host、Service 与访问边    │ 概览              │
│ Nodes        │                                   │ SSH 账户与地址     │
│ Activity     │ 自动布局、缩放、选择、异常聚焦    │ 授权与主机信任     │
│              │                                   │ 服务与历史          │
└──────────────┴───────────────────────────────────┴───────────────────┘
```

侧边栏只保留：

- **Graph**：默认入口，以关系为中心。
- **Nodes**：同一数据的列表/表格管理入口。
- **Activity**：正在运行、等待恢复、失败和本机审计事件。

Settings 继续使用独立 Scene。Keys 和 Devices 不消失，而是成为 Graph 节点与 Inspector 中的领域信息。

### 3.2 Graph 画布

- 当前设备视图把当前 Mac 放在中心，显示到所有 Host 的候选或已验证访问边。
- 全部设备视图显示每台 KeyPort 设备的独立授权覆盖。
- 服务视图展开 Saved Service，并显示直连或受控隧道入口。
- 同一 Host 的多个 Address 和 SSH Account 默认折叠；点击节点或边后在 Inspector 中展开。
- Merge Review、Host Key 变化、无可用路由和待清理 Tunnel 在节点上明确标识并阻断动作。
- 搜索可匹配 Host、地址、SSH 用户、别名、服务、设备和公钥指纹。
- 自动布局是 P0；手工位置同步不进入首版 schema。

### 3.3 Nodes

Nodes 是 Graph 的文本等价视图，不是旧 Servers 页换名：

- Host 行可展开 Address、SSH Account 和 Saved Service。
- Device 行可展开 Key 和其 Authorization。
- 支持排序、批量选择、键盘操作、VoiceOver 和复制稳定别名。
- Graph 选中项与 Nodes 选择保持同一个稳定实体 ID。

### 3.4 Inspector

选中 Host 时展示：

1. **概览**：名称、分组、机器配置、authority/merge 状态。
2. **访问**：地址选择、SSH Account、当前设备与其他设备 Authorization。
3. **信任**：Host Key Pin、KnownHostsLine 来源和变化历史。
4. **服务**：Saved Service、直连/隧道计划和活动 lease。
5. **历史**：Reachability、Connection History 和 Audit。

选中 Device、Service 或访问边时使用对应的精简 Inspector；任何可操作状态都显示证据来源和下一步。

### 3.5 统一新增向导

所有入口都发起同一个接入会话，可带预填参数：

1. 新建或选择 Host。
2. 添加/选择 Access Address。
3. 输入 SSH 用户和别名。
4. 扫描并确认 Host Key。
5. 使用密码或已有密钥证明账号可控。
6. 原子提交 Host v6 实体。
7. 可选立即启用当前设备密钥访问。

SSH Config 导入和 Tailscale 建议只负责预填，不再各自维护一套保存与授权流程。

### 3.6 动作命名

| 当前文案 | 目标文案 | 领域意图 |
| --- | --- | --- |
| 添加服务器 | 添加主机 | 创建 Host，并在同一向导中添加首个 SSH Account |
| 添加用户 | 添加 SSH 账户 | 在现有 Host 下创建 SSHIdentity |
| 检测免密 | 验证密钥访问 | 只检查当前设备，不修改远端 |
| 启用免密 | 启用密钥访问 | 必要时安装当前设备公钥并复验 |
| 同步 SSH 授权 | 授权当前设备 | 明确这是远端写操作，不是 Cloud 同步 |
| 同步 CloudKit 元数据 | 同步工作区 | 同步非秘密 Host v6 元数据 |

辅助文案可以继续使用“免输密码登录”，但领域代码不再把“免密”当成授权类型。

## 5. 深模块

### 5.1 `TopologyGraphProjector`

输入 `HostV6.MetadataEnvelope`、当前设备 ID 和 Graph 查询，输出不可变 `TopologyGraphSnapshot`。它内部完成：

- Host/Device/Service 节点生成。
- Device → Key → Authorization → SSH Account → Host 连接。
- 当前设备候选边。
- Node Association、Merge Review 和 Host Key 阻断摘要。
- 视图模式、过滤、折叠和状态优先级。

View 不应重复拼接这些关系。

### 5.2 `EnrollmentCoordinator`

对外只暴露开始、推进、恢复和取消接入会话。DNS/TCP、Host Key、密码/密钥证明、临时 known_hosts、Keychain 保存和 Host v6 原子提交留在模块内部。

该模块需要 Host v6 新增/更新命令支持，不能直接绕过 `MetadataRepository.transact`。

### 5.3 `AccessCoordinator`

对外表达三个意图：

- 确保当前设备能够访问一个 SSH Account。
- 重新验证已有账号授权。
- 撤销一个明确的 Authorization。

它吸收当前 `PasswordlessPrimaryAction` 和 AppModel 执行代码，内部协调 Host Trust、LocalAuthentication、Keychain、SSH Key、OpenSSH、Authorization、SSH Config 和 Activity。

### 5.4 `GraphWorkspaceModel`

只持有选择、搜索、过滤、显示模式、Inspector 和 OperationRun。它可以观察 repository snapshot 和 coordinator 进度，但不拥有领域数据。

### 5.5 `OperationRun`

替换单一 `isBusy`：

- 类型：enrollment、keyAccess、revoke、sync、discovery、tunnel、archive。
- 范围：Host、SSH Account、Device、Service 或 workspace。
- 阶段、逐项目标、进度、取消能力、恢复标识和结构化失败。

两个任务只有在资源范围或外部适配器冲突时才互斥。

## 7. 写权与迁移策略

本次改版不发明新的 V7 数据模型；它完成已经设计和实现的 v5 → v6 切换。

### 7.1 Canary 阶段

1. 从影子 `MetadataEnvelope` 生成只读 Graph。
2. Graph 节点可深链到现有账号详情和状态感知动作。
3. 所有领域写仍遵守 legacy authority；Graph 不直接修改 V6。
4. 对影子迁移冲突、缺失路由和 notRepresentable 实体提供可视化诊断。

### 7.2 V6 写路径完备

在新 UI 获得写权前补齐 `ModelCommand`：

- 创建/更新 Host。
- 创建/更新/删除 Address，并处理引用策略。
- 创建/更新 SSH Account，并保持别名唯一和旧 ID 继承。
- 确认/替换 Host Key Pin 和 KnownHostsLine。
- 创建/更新 Saved Service。
- 提交/更新 Authorization 的成功证据。
- 更新 Node Association 和本机状态的受控入口。

命令必须继续具备 expected revision、command/mutation ID、journal 和 pending effects；不能为 UI 方便引入数组 setter。

### 7.3 Authority 激活

1. 完成 JODER-10 C3 的两台团队签名 Mac 验收。
2. 验证 V5/V6、V6/V6、Cloud change tag、Keychain account、Authorization 和 Node Association 无损。
3. 签发并发布 authority manifest。
4. GraphWorkspace 切换为 V6 原生读写。
5. Compatibility snapshot 只在恢复或旧 UI 短暂并行期使用。

### 7.4 清理

新 UI 和 V6 原生写路径达到删除门槛后，直接删除旧页面、AppModel 大部分逻辑和 V5 运行时写路径，不保留永久 Legacy Mode。Post-authority 回滚继续遵守现有“只读兼容 + 前向恢复”，不能恢复 V5 写权。

## 8. 分阶段实施

每个阶段单独建立 Issue、分支和 PR。

### 阶段 0：设计基线

- 统一术语、Graph 投影、接入/授权流程、UI 改版和切换计划。
- 对齐 Host v6 已有契约。

完成条件：本文不再提出与当前 Host v6、Cloud v2 或 authority 相冲突的第二套模型。

### 阶段 1：纯 Graph 投影

- `TopologyGraphSnapshot/Projector/Query`。
- Host v6 fixtures 覆盖多设备、多账号、服务、Node Association 和 blockers。
- 自动布局输入模型，不接 SwiftUI。

完成条件：给定 MetadataEnvelope，可稳定生成节点、边、状态和证据摘要。

### 阶段 2：Host v6 创建与更新命令

- 补齐 Host、Address、SSH Account、Pin、Service 和 Authorization 命令。
- revision、冲突、journal、pending effects 和 Cloud merge 测试。

完成条件：新增/编辑不需要直接改数组或回写 V5。

### 阶段 3：应用编排

- `EnrollmentCoordinator`。
- `AccessCoordinator`。
- `OperationRun` 和资源级并发。
- 复用现有平台适配器。

完成条件：无 UI 也能测试新增、已有密钥、密码授权、Host Key 阻断、部分失败、取消和恢复。

### 阶段 4：新 UI

- Workspace、Graph、Nodes、Inspector、Enrollment、Activity。
- Canary 只读模式和 authority 状态。
- 键盘、VoiceOver、Reduce Motion 和最小窗口尺寸。

完成条件：在 Canary 下可完整浏览；在测试 repository 下可完成单设备闭环。

### 阶段 5：C3 与多设备切换

- 两台签名 Mac 的 V5/V6、V6/V6、CloudKit 和 iCloud Keychain 验收。
- Authority 激活和 Graph 原生写路径。
- Mac 1/Mac 2/A/B/C 场景和批量授权。

完成条件：同步、私钥隔离、独立 Authorization 和冲突恢复均有真实证据。

### 阶段 6：删除旧 UI 和 V5 写路径

- 删除旧 Features、集中式 AppModel 编排和 compatibility-driven UI。
- 更新 README、DESIGN、截图、归档和发布检查。

完成条件：运行时只有 Host v6 一个领域事实源和 GraphWorkspace 一套主 UI。

### 阶段 7：可选拓扑增强

- 用户确认的服务依赖关系。
- 自定义布局同步。
- 更大规模图的聚类和性能。

这些需求需要独立 schema/安全评审，不阻塞 P0 Graph。

## 9. 删除门槛

只有全部满足后才删除旧 UI 和 V5 写路径：

1. Host v6 create/update/authorize 命令和迁移 fixture 全部通过。
2. 新 UI 覆盖新增、编辑、删除、验证、授权、撤销、同步、服务和冲突处理。
3. Graph 信息在 Nodes/Inspector 中有完整文本等价。
4. AskPass、Host Key、SSH Config、Cloud v2、Tunnel 和归档回归通过。
5. C3 双 Mac authority 证据通过，且没有未解决阻断性 Merge Review。
6. 新 UI 在 canary、authoritative、compatibility rollback 三种模式下行为正确。
7. Release 构建、签名包启动和真实 Linux/OpenSSH 验收通过。

达到门槛后删除旧测试和代码，不保留两套长期行为。

## 10. 验证矩阵

### 10.1 自动检查

- Graph：稳定 ID、折叠、候选边、状态优先级和证据追踪。
- Enrollment：Host Key 先于密码、临时 known_hosts、已有密钥、密码失败、取消和恢复。
- Access：先验证后安装、幂等、复验失败、漂移、撤销和缺少私钥。
- Host v6 commands：revision、并发、墓碑、外部效果、command replay 和 invariant。
- Sync：V1 单向输入、V2 向量合并、Merge Review、payload 门禁和 authority。
- UI：Graph/Nodes 选择一致、逐项任务、空状态、错误、键盘和无障碍。
- Security：Graph snapshot、Cloud payload、日志和归档不含密码/私钥。

### 10.2 仓库检查

```bash
./script/test.sh
./script/test_c4.sh
swift build -c release
./script/build_and_run.sh --verify
git diff --check
```

文档或纯投影变更可按风险裁剪，但涉及 UI、authority、SSH 或 Tunnel 时必须执行对应完整门禁。

### 10.3 真实环境

- 两台登录同一 Apple ID、使用团队签名构建的 Mac。
- V5/V6 和 V6/V6 写权切换。
- 多个 Linux/OpenSSH 版本、Ed25519/RSA、密码禁用和异常中断。
- iCloud 延迟、离线、冲突、账号退出和 iCloud Keychain 开关。
- Host Key 轮换、地址漂移、Tailscale node ID 变化和并发修改。
- 服务直连、隧道目标失败、主应用崩溃和 lease 清理。

## 11. 风险与控制

| 风险 | 控制 |
| --- | --- |
| Graph 与 Host v6 各自维护关系 | Graph 只能读取 projector 输出，写入必须走 ModelCommand |
| 用户把边误解成实时网络路由 | 边有类型和证据，Authorization、Node Association、Reachability 分开展示 |
| Canary Graph 意外取得写权 | UI 显示 authority mode，repository 强制拒绝 |
| 全量 UI 改版破坏安全流程 | 应用编排复用现有适配器，并先通过无 UI 行为测试 |
| AppModel 拆分形成多个浅包装 | 以 Enrollment/Access/Graph 三个小 interface 隐藏完整行为 |
| Cloud payload 随 Graph 布局膨胀 | P0 布局本地确定性计算，不写 Cloud；继续执行 800 KiB 门禁 |
| 多账号导致画布爆炸 | Host 为主节点，账号和地址默认折叠到边/Inspector |
| 新服务关系扩大远程执行范围 | Saved Service 只使用既有直连/受控隧道，不增加任意命令 |
