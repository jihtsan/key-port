# KeyPort APP 功能全景与产品 Review
- 盘点日期：2026-08-21
- 盘点基线：当前工作区源码，而不是仅依据需求文档或 README
- 产品阶段：macOS 一期 MVP
- 支持系统：macOS 14+
- 说明：本文区分“界面中可操作的功能”“后台已实现但没有入口的能力”“需求中提出但当前尚未闭环的能力”

## 1. 产品定位与边界

KeyPort 是一款 macOS 原生 SSH 入口与免密授权管理工具。它负责：

1. 管理服务器端点、SSH 账户和稳定别名。
2. 确认服务器 Host Key，阻止未知或变化后的主机身份继续认证。
3. 发现、导入或生成当前 Mac 的 SSH 密钥。
4. 使用一次密码认证，把当前 Mac 的公钥安装到远端账户。
5. 验证免密登录，生成独立的 SSH Config。
6. 识别多台 Mac 的密钥和远端授权，并精确撤销单把公钥。
7. 同步不含秘密的元数据，并可选同步 Keychain 中的服务器密码。
8. 提供本地审计日志与加密元数据归档。

KeyPort 明确不做以下事情：

- 不提供内置终端或交互式 Shell。
- 不提供任意远程命令执行界面。
- 不保存或同步私钥内容。
- 不把密码放入 CloudKit、应用状态、SSH Config、命令参数或普通日志。
- 不定位为 CPU、内存、磁盘、进程或业务指标监控工具。当前展示的机器配置只是 SSH 连接的辅助信息。

## 2. 当前信息架构

| 一级入口 | 主要对象 | 核心任务 | 当前完成度 |
| --- | --- | --- | --- |
| 服务器 | 服务器端点下的 SSH 账户 | 添加、验证、授权、撤销、复制别名 | 核心闭环已实现，体验仍有缺口 |
| 密钥 | SSH 连接和本地身份密钥 | 发现、生成、导入、查看、加载 Agent | 基础能力已实现，生命周期管理不完整 |
| 设备 | KeyPort 设备与 Tailscale 节点 | 查看设备、关联账户、批量授权 | 发现与关联较完整，设备治理和批量反馈不足 |
| 审计日志 | 本地结构化事件 | 查看操作结果、清理日志 | 基础记录已实现，检索与诊断能力较弱 |
| 设置 | 本机、同步、安全、归档 | 配置 iCloud、Keychain、归档和剪贴板策略 | 基础设置已实现，存在无效或缺失项 |
| 菜单栏 | 已授权 SSH 账户 | 快速复制别名、打开或退出应用 | 已实现，但漏掉未分组账户 |

主窗口采用三栏结构：左侧一级栏目、中间对象列表、右侧详情。窗口最小尺寸为 980 x 620，默认尺寸为 1180 x 760。

## 3. 全局能力

### 3.1 启动与本地状态

- 启动时读取 `~/Library/Application Support/KeyPort/state-v1.json`。
- 本地状态采用版本化 JSON，保存服务器、设备、公钥元数据、授权关系和审计事件。
- 自动创建或恢复当前 Mac 的永久设备 ID。
- 启动时扫描本地 SSH 公钥、私钥配对、SSH Agent 和 SSH Config 连接。
- 启动时读取 Keychain 中每个服务器密码是否存在，以及是否允许同步。
- 自动读取 Tailscale 状态。
- 对已授权且机器配置超过 24 小时未更新的账户，后台尝试刷新机器配置；失败后同样等待下一周期，避免频繁重试。
- iCloud 元数据同步开启时，启动完成后自动安排同步。
- 本地状态目录按 `0700`、状态文件按 `0600` 权限保存。

### 3.2 全局导航和操作状态

- 侧边栏固定包含“服务器、密钥、设备、审计日志”。
- 全局工具栏右侧提供“同步元数据”。
- 任一耗时操作进入全局忙碌状态时，右侧按钮替换为小型进度指示器，部分冲突操作会被禁用。
- 失败通过统一的“KeyPort 无法完成此操作”弹窗显示。
- 列表分别处理“没有数据”和“搜索无结果”等空状态。
- 服务器命令菜单提供密码检查、密钥检查、复制别名和授权入口，并配置键盘快捷键。

### 3.3 全局 Review

1. `[P1]` 全局“同步元数据”在同步关闭时仍然显示，点击后没有可见反馈。建议显示当前同步状态，关闭时改为“开启同步”或直接隐藏。
2. `[P1]` `isBusy` 是单一全局锁。归档、扫描、Tailscale、CloudKit 和单账户 SSH 操作的互斥边界不够清晰，部分方法又没有进入该状态。建议改成可枚举的活动任务状态，并按资源冲突禁用操作。
3. `[P2]` 错误统一落到一个弹窗，但没有稳定的“阶段、对象、建议动作”结构。建议错误模型携带操作阶段和恢复入口。
4. `[P2]` 当前没有统一的操作成功反馈；复制、同步、扫描、导入等反馈方式不一致。

## 4. 服务器栏目

服务器栏目是产品主流程，数据边界是“一个 `ServerConnection` 代表一个端点上的一个 SSH 账户”。同一主机和端口下的多个账户在界面中聚合展示，但密码、别名、密钥授权和检测状态仍然按账户隔离。

### 4.1 服务器列表

已实现：

- 按标准化后的 `host + port` 聚合账户；主机名忽略大小写和末尾点号。
- 单账户端点使用一行紧凑显示：服务器名称、地址、用户、别名和授权状态。
- 多账户端点使用一个服务器标题加多个账户行，标题显示地址、用户数和机器容量摘要。
- 多账户按用户名、别名排序；服务器组按代表记录的名称排序。
- 搜索实际覆盖名称、主机、用户、分组和 SSH 别名。
- 状态同时使用图标、颜色和文字，不只依赖颜色。
- 行右键菜单提供：编辑用户、添加用户、复制 SSH 别名、删除用户。
- 多账户标题提供编辑服务器和添加 SSH 用户按钮。
- 顶部工具栏提供：添加服务器、添加用户、检查密码 SSH、检查免密登录、编辑用户、授权此 Mac。
- `Command-N` 可添加服务器；服务器命令菜单还提供密码检查、密钥检查、复制别名和授权快捷键。

细节与边界：

- 同一端点的服务器名称、主机、端口、分组、备注、Host Key 和机器配置被视为共享字段。
- 编辑其中一个账户的共享字段时，会同步更新同端点的其他账户。
- 用户名、别名、密码、密码检测、密钥检测和授权状态不共享。
- 删除账户采用软删除标记，保留同步版本信息；随后删除对应 Keychain 密码并重写 KeyPort SSH Config。
- 删除账户不会删除本地密钥，符合“密钥可能仍被其他账户使用”的边界。

Review：

1. `[P0]` “删除用户”没有二次确认，却会隐藏账户、尝试删除密码并重写配置。建议弹窗明确列出账户、别名、是否有保存密码、是否有已知远端授权，以及“不会自动删除远端公钥”。
2. `[P0]` Keychain 删除错误被忽略。账户可能已删除但密码仍残留。应在删除凭据失败时阻止完成，或明确提示并提供清理入口。
3. `[P1]` 搜索提示写的是“名称、地址、用户、分组”，实际还支持别名。应补上“别名”。
4. `[P1]` 后台已有 `checkAll()`，界面没有“检测全部”入口；需求中的批量检测尚未对用户开放。
5. `[P1]` 列表复制别名没有原位成功反馈或 VoiceOver announcement，菜单栏却已经有 1.5 秒的勾选反馈。建议复用同一复制组件。
6. `[P2]` 多账户端点依赖一条“代表记录”提供标题。历史数据若共享字段不一致，标题可能随代表记录变化。应在数据层强制共享字段一致或引入独立端点对象。

### 4.2 添加服务器和首个用户

输入项：

- 服务器名称。
- 主机名或 IP。
- 分组。
- SSH 端口，范围 1 到 65535，默认 22。
- SSH 用户名。
- SSH 别名。
- 服务器密码。
- 是否允许通过 iCloud Keychain 同步该密码。
- 可选备注。

校验与自动行为：

- 名称、主机和用户名必填。
- SSH 别名只允许小写字母、数字和单个连字符，不能以连字符开头或结尾，也不能重复连字符。
- 别名根据分组、名称和用户名自动建议；用户手动编辑后停止自动覆盖。
- 自动避开 KeyPort 已管理的别名。
- 检查 `~/.ssh/config` 中已有的字面 Host 别名冲突。
- 检查相同端点、端口和用户名是否已经存在。
- 新建服务器必须输入密码并成功完成 SSH 检查后才能保存。
- 首次检查先执行 Host Key 扫描；用户明确确认指纹后才继续密码认证。
- 密码检查只允许 password authentication，禁用公钥、SSH Agent 和 keyboard-interactive 回退，避免“已有密钥成功”被误判为密码正确。
- 密码验证成功后尝试读取远程主机名、系统、内核、架构、CPU 数和内存。
- 保存时把密码写入 Keychain、Host Key 写入专用 `known_hosts`、元数据写入本地快照。
- 新建后状态通常为“需要授权”；如果当前 Mac 没有可用密钥，则为“缺少本地密钥”。

Review：

1. `[P1]` 当前“检查 SSH”把 Host Key 扫描、密码认证和机器信息采集合并成一个动作，日志虽有阶段，但主界面没有明确的步骤状态。建议显示“连接端点 -> 确认身份 -> 验证密码 -> 读取配置”四步进度。
2. `[P1]` 在编辑器中接受 Host Key 后，成功检查前会先写专用 `known_hosts`。若用户随后取消新建，可能暂时留下没有对应服务器记录的主机条目。建议只在保存事务中提交，检查阶段使用临时 known_hosts。
3. `[P2]` 备注属于同端点共享字段，但界面没有说明。多账户用户可能以为备注只属于当前账户。

### 4.3 为已有服务器添加用户

- 从所选端点复制名称、主机、端口、分组、备注和已确认 Host Key。
- 服务器字段锁定，只允许填写新的用户名、账户别名和密码。
- 自动生成账号级别名并避开现有别名。
- 新账户仍需独立完成密码 SSH 检查。
- 保存后形成新的账户记录和独立 Keychain 密码。
- 同一端点不能重复添加相同用户名。

Review：

1. `[P2]` 弹窗隐藏备注，但备注又从源账户复制并作为共享字段存在，用户看不到此次保存携带了什么备注。
2. `[P2]` 如果端点有多个账户，添加入口同时出现在标题按钮、账户右键菜单和工具栏，功能重复但目标上下文并不总是清楚。建议统一为端点级“添加账户”。

### 4.4 编辑服务器和用户

- 可修改名称、主机、端口、分组、用户名、别名和备注。
- 仅修改名称、分组、别名或备注时，可以不重新输入密码，直接保存元数据。
- 主机、端口或用户名变化时，必须重新完成 Host Key 和密码检查。
- 主机或端口变化会清除同端点其他账户的认证状态，要求逐账户重新检查。
- 可保留现有密码，也可输入新密码。
- 不更换密码时可以在“本机 Keychain”和“iCloud Keychain 可同步项目”之间迁移存储方式。
- 修改别名后重写 KeyPort 管理的 SSH Config。

Review：

1. `[P1]` 修改 SSH 别名会使脚本、书签和自动化引用失效，当前没有风险提示。
2. `[P1]` 接受 Host Key 轮换的内联界面只展示新指纹，没有像独立确认弹窗一样并排展示旧指纹和新指纹。
3. `[P2]` 共享字段更新会批量影响同端点账户，但保存前没有变更影响摘要。

### 4.5 服务器详情

当前详情从上到下包含：

1. 账户标题：服务器名称、`user@host:port`、综合密钥授权状态。
2. 连接：别名、主机、端口、用户、分组、生效配置和身份密钥路径。
3. 最近失败或进行中的 SSH 检查日志。
4. 机器配置：主机名、系统、内核、架构、CPU、内存和同步时间。
5. 设备与 SSH 账户：匹配的设备、Tailscale 地址、同设备上的其他账户和跨栏目跳转。
6. 用户密码：Keychain 是否存在密码，添加或更新密码。
7. 登录验证：密码登录和免密登录各自的状态、原因、时间和操作按钮。
8. 主机身份：已确认算法和 SHA256 指纹。
9. 当前 Mac：所用密钥、指纹、状态详情；没有密钥时可生成 Ed25519。
10. 设备授权：读取到的 KeyPort 远端授权、设备、密钥、指纹、跳转和撤销按钮。

可复制内容：

- SSH 别名。
- 主机地址。
- 指纹和密钥文本可使用系统文本选择。

Review：

1. `[P1]` 信息顺序把高频的“登录验证”和“下一步操作”放在机器配置、设备关联之后。建议首屏顺序改为：账户摘要 -> 快速访问与验证 -> 安全证据 -> 连接配置 -> 关联信息 -> 运维信息。
2. `[P1]` 详情中的复制按钮没有成功状态，用户无法确认是否已复制。
3. `[P1]` 服务器备注可编辑但详情完全不显示。
4. `[P1]` Host Key 详情不显示首次确认时间和最近见到时间，也没有保留可查看的旧指纹历史。
5. `[P1]` “更新密码”只能用新密码覆盖，没有“删除已保存密码”。需求中的授权成功后删除密码尚未实现。
6. `[P2]` “Show key”等少量 tooltip，以及密钥详情的部分标题仍为英文，需统一中文。
7. `[P2]` 机器配置是辅助信息，不宜排在认证和安全状态之前，以免产品看起来像轻量监控工具。

### 4.6 密码管理弹窗

- 密码始终使用 SecureField，不明文显示。
- 保存前必须用当前输入值完成一次密码 SSH 测试。
- 用户编辑密码后，旧测试结果立即失效，避免把 A 密码的成功结果用于保存 B 密码。
- 测试过程中禁用输入和保存。
- 可选择只保存，或保存后立刻授权当前 Mac。
- Host Key 未确认或发生变化时，测试会被阻止。
- 密码保存为以稳定服务器 UUID 为 account 的 Keychain 项目。
- 真实团队签名和 Keychain entitlement 可用时，用户可以选择 synchronizable 项目。

Review：

1. `[P0]` 从 SSH Config 导入连接后会立即打开密码弹窗，但该连接还没有确认 Host Key。弹窗只会提示“先确认”，却没有确认入口，用户必须取消、回服务器执行检查、再回来保存密码。应把 Host Key 确认纳入同一向导。
2. `[P0]` 单账户授权和批量授权会显式请求 Touch ID/系统密码，但普通“检查密码 SSH”读取新保存的 Keychain 项目时没有显式本地身份验证。新项目使用 `AfterFirstUnlock`，没有配置 user-presence access control。实现与“每次读取保存密码前验证本机身份”的安全表述不完全一致。
3. `[P1]` 没有删除密码、查看密码或复制密码入口；因此“敏感剪贴板自动清理”当前也没有实际消费场景。
4. `[P2]` 更新已有密码时，同步开关默认取全局新密码策略，而不是当前项目的同步状态；独立密码弹窗没有传入现有状态，容易无意改变策略。

### 4.7 Host Key 管理

- 使用系统 `ssh-keyscan`，超时 5 秒。
- 支持同一端点返回多个 Host Key 算法。
- 指纹使用 OpenSSH SHA256 形式。
- 第一次遇到的指纹为“待确认”。
- 已确认算法出现新指纹时为“主机密钥已变更”，停止认证。
- 新增了尚未确认的算法时同样要求确认。
- 独立确认弹窗在轮换时并排显示此前指纹和当前扫描结果。
- 确认后写入 `~/.ssh/keyport/known_hosts`，权限 `0600`。
- 所有 SSH 认证强制 `StrictHostKeyChecking=yes`，禁用全局 known_hosts。
- 轮换动作会写审计事件，并在确认后重新执行原本的密码或密钥检查。

Review：

1. `[P0]` 当前数据模型只保留“现行确认集合”。接受轮换后旧指纹被覆盖，审计事件只记录“确认了几项”，无法恢复需求中的指纹历史证据。
2. `[P1]` 详情未展示 `firstConfirmedAt` 和 `lastSeenAt`。
3. `[P1]` 服务器详情没有主动“重新扫描 Host Key”或“查看轮换历史”的专用动作，只能借认证检查触发。

### 4.8 密码检查、密钥检查和综合状态

密码检查：

- 先扫描并验证 Host Key。
- Keychain 没有密码时打开密码弹窗。
- 仅测试密码认证，不允许公钥或 Agent 兜底。
- 成功后尝试刷新机器配置。
- 结果单独保存在 `passwordCheck`，显示状态、详情和检查时间。

密钥检查：

- 先扫描并验证 Host Key。
- 选择当前账户已知授权密钥、SSH Config 对应密钥或当前默认候选密钥。
- 仅测试明确的私钥文件，不允许密码、keyboard-interactive 或 SSH Agent 兜底。
- 成功后更新账户为“已授权”、写入授权关系并生成 SSH Config。
- 失败后通常更新为“需要授权”；没有本地密钥则为“缺少本地密钥”。
- 网络或 SSH 运行错误会更新为“无法连接”。

综合状态模型包含：已授权、需要授权、缺少本地密钥、主机密钥待确认、主机密钥已变更、无法连接、密码验证失败、密钥验证失败、授权冲突、等待同步和检查中。

Review：

1. `[P1]` `密码验证失败`、`密钥验证失败`、`授权冲突` 已定义并有 UI 样式，但当前业务路径没有写入这些综合状态，属于预留死状态。应删除、实现或明确只用于未来迁移。
2. `[P1]` 密码检查失败不会改变列表综合状态，列表可能继续显示“已授权”，详情才显示密码失败。这在“授权状态”和“凭据健康度”两个概念上是合理的，但界面需要明确区分，避免误认为状态未刷新。
3. `[P2]` 检查成功后日志被隐藏，用户只能看到摘要；失败日志保留在全局单一槽位，切换或执行另一个账户检查会覆盖。

### 4.9 授权当前 Mac

- 必须已有确认的 Host Key、可用私钥和 Keychain 密码。
- 单账户授权前请求 Touch ID 或 Mac 登录密码。
- 密码经权限受限的一次性 FIFO 交给 `KeyPortAskPass`，不放入命令参数。
- 远端创建 `~/.ssh` 和 `authorized_keys` 时设置 `0700/0600`。
- 按公钥 blob 查重，同一公钥不会重复写入。
- 写入前备份原文件，使用同目录临时文件和原子替换。
- 保留未知行、未知选项和未知公钥。
- 写入后在远端再次验证公钥存在。
- 随后再执行一次仅公钥 SSH 认证；只有验证成功才标记“已授权”。
- 成功后写授权关系并生成本机 SSH Config。
- 没有当前设备密钥时，部分入口会自动生成 Ed25519 密钥；服务器工具栏入口则要求状态已经是“需要授权”。

Review：

1. `[P1]` 授权入口分布在服务器工具栏、服务器详情、密钥详情和设备详情，禁用条件并不完全一致。建议集中到共享的授权动作策略，所有入口显示同一原因。
2. `[P1]` 如果安装公钥成功但最终密钥验证失败，界面只报失败；远端可能已经存在公钥。应提供“已写入但验证失败”的独立可恢复状态和清理/重试入口。

### 4.10 读取和撤销远端授权

- 仅在当前账户已授权且当前 Mac 有本地私钥时允许刷新。
- 读取远端 `authorized_keys`。
- 只把 `keyport:v1:<keyID>:<device>` 备注识别为 KeyPort 管理项。
- 按公钥指纹合并本地和远端记录。
- 发现其他设备的 KeyPort 公钥时，创建只有公钥元数据的远程密钥记录。
- 远端已消失的已知授权转成 tombstone，避免云端旧状态复活。
- 撤销前请求本机身份验证，并再次确认 Host Key。
- 撤销只删除公钥 blob 完全匹配的行，保留其他内容。
- 修改前备份、原子替换，并在远端验证目标已消失。
- 撤销当前 Mac 自己的登录密钥后，账户变成“需要授权”，并重写 SSH Config。

Review：

1. `[P1]` 当前只能读取 KeyPort 管理的授权；未知公钥虽然被安全保留，但详情不会显示其数量或存在性。建议只读展示“另有 N 项非 KeyPort 授权”，帮助用户理解文件全貌。
2. `[P1]` 撤销其他设备密钥依赖当前 Mac 自己仍有可用登录密钥，这一前置条件应在按钮附近说明。
3. `[P2]` 远端备份会持续累积，没有保留数量或清理策略。

## 5. 密钥栏目

### 5.1 列表结构

列表混合展示两类对象：

1. “SSH 连接”：从用户 SSH Config 发现的连接，以及所有 KeyPort 服务器账户。
2. “本地身份密钥”：当前快照中的公钥记录，包括本地可用密钥和云端同步来的远程公钥元数据。

SSH 连接行显示：

- 别名、主机和端口。
- 是否存在已知授权。
- 是否已经加入服务器栏目。
- 未授权且没有保存密码时的警告。
- 对尚未管理的 SSH Config 连接提供“添加到服务器”按钮。

本地身份密钥行显示：

- 密钥名称。
- 本地或云端形态图标。
- 首个关联 SSH Config 连接，或公钥指纹。

Review：

1. `[P1]` “密钥”栏目同时以“连接”和“密钥”为一级对象，心智模型混合，并与服务器栏目重复。建议主列表只管理身份密钥，把 SSH Config 发现放到独立的“导入连接”流程或服务器栏目。
2. `[P1]` 没有搜索、类型筛选、本地/远程筛选或排序选项，密钥数量增加后难以管理。

### 5.2 SSH Config 发现和导入

- 读取 `~/.ssh/config` 中的字面 `Host` 别名，忽略通配符和否定模式。
- 对每个别名执行 `ssh -G -- <alias>`，获得最终生效的主机、端口、用户和 IdentityFile。
- 保留一个连接配置中的多个 IdentityFile。
- 如果别名已经匹配 KeyPort 服务器，则合并成一行。
- 未管理连接可以一键添加为服务器元数据，并随后请求密码。
- 从 SSH Config 导入的原始别名会尽量保留。

Review：

1. `[P0]` 导入后的 Host Key/密码向导断裂，详见 4.6。
2. `[P1]` 只从主配置文本枚举 Host；虽然 `ssh -G` 会解析 Include，但 Include 文件中的别名不会被主动枚举。建议实现递归、带循环保护的配置解析，或使用专门的导入选择器。
3. `[P1]` “扫描密钥”按钮吞掉扫描错误，用户不会看到失败原因。

### 5.3 扫描本地密钥

- 递归扫描 `~/.ssh` 下深度不超过三层的 `.pub` 文件。
- 解析 Ed25519、RSA 和其他可识别的 OpenSSH 公钥。
- 同目录存在去掉 `.pub` 后的文件时，记录为有本地私钥。
- 读取 `ssh-add -L`，把 Agent 身份合并进同指纹记录。
- 以 SHA256 指纹去重。
- KeyPort 注释中的稳定 key ID 会被复用。
- 启动时自动扫描，也可通过工具栏手动扫描。

Review：

1. `[P0]` 如果一个此前可用的私钥文件后来被删除，扫描合并会把旧记录原样保留，可能继续显示为“本地可用”。应把未再次发现的本地记录降级为不可用，并清除失效路径/Agent 状态。
2. `[P1]` Agent-only 密钥会被标记为本地可用，但密钥检查明确禁用 Agent 且要求私钥路径。界面可能展示可用，实际认证却报缺少私钥。需要把“可列出”“可用于 KeyPort 直连”“存在可管理私钥”拆成不同状态。
3. `[P1]` 没有展示或检查扫描到的原始私钥权限，也没有修复入口。

### 5.4 生成密钥

- 每次生成新的稳定 key ID。
- 使用 `ssh-keygen -t ed25519`。
- 文件保存到 `~/.ssh/keyport/identities/<keyID>`。
- 私钥权限设为 `0600`。
- 公钥备注为 `keyport:v1:<keyID>:<设备标识>`。
- 新密钥自动成为最近选择的候选密钥。
- 生成后把“缺少本地密钥”的服务器更新为“需要授权”。

Review：

1. `[P0]` 生成命令使用空口令，私钥仅依赖文件权限保护；与需求中“标准 OpenSSH 加密格式或等价设备本地保护”的表述存在差距。需要明确产品安全策略，或增加私钥口令/Keychain/安全硬件方案。
2. `[P1]` 当前没有“默认密钥”设置。用户在密钥列表中最后选择的本地密钥会隐式优先用于后续授权，这一副作用没有提示。应显式选择设备默认密钥，或按账户选择密钥。
3. `[P2]` 可以无限生成密钥，但没有命名、用途标签或清理机制。

### 5.5 导入私钥

- 系统文件面板选择私钥。
- 必须存在同路径的 `.pub` 文件。
- 当前支持 Ed25519 和 RSA。
- 以公钥指纹拒绝重复导入。
- 私钥复制到 KeyPort identities 目录并改为 `0600`。
- 公钥重写为 KeyPort 标准备注，权限为 `0644`。
- 原文件不删除。

Review：

1. `[P0]` 当前只验证相邻公钥，没有验证所选私钥本身能否解析、是否与公钥匹配。应使用 `ssh-keygen -y` 做一致性验证。
2. `[P0]` 加密私钥可能成功导入，但后续 BatchMode 公钥认证没有私钥口令输入通道，也没有本地 Keychain 口令管理，实际不可用。应在导入时明确拒绝或完整支持。
3. `[P1]` 导入前没有展示指纹、类型、目标路径和重复关联摘要。

### 5.6 密钥详情和 Agent

- 展示名称、所属设备、类型、来源、指纹、私钥路径、Agent 状态和完整公钥。
- 可跳转到所属设备。
- 有私钥且尚未加载时，可以执行 `ssh-add <path>`。
- 展示该密钥已知授权的 SSH 账户，并可跳转服务器详情。

Review：

1. `[P0]` 没有删除密钥能力，也没有“仅从 KeyPort 移除”和“删除本机私钥文件”的安全分层。
2. `[P1]` 没有专用的复制公钥、复制指纹按钮和复制反馈，只能手动选择文本。
3. `[P1]` 加载 Agent 失败时有全局错误，但没有处理私钥口令的流程。
4. `[P1]` 缺少服务器关联和远端授权风险评估，因而也无法安全实现删除。
5. `[P2]` 部分标题和空状态仍为英文，应统一中文。

### 5.7 SSH Config 写入

- 只生成 `~/.ssh/keyport/config`，不重写用户已有 Host 段。
- 主配置只插入一条 `Include ~/.ssh/keyport/config`。
- Include 放在用户 Host 段之前，避免既有 `Host *` 提前覆盖。
- Include 检测支持空白和引号差异，操作幂等。
- 写入主配置和托管配置前创建带时间戳备份。
- 使用临时文件原子替换，权限 `0600`。
- 只为本机有私钥且授权状态为已授权的关系生成 Host。
- 同一账户存在多把本机授权密钥时，合并成一个 Host 段和多个 IdentityFile。
- 每个 Host 强制 `IdentitiesOnly yes` 和 KeyPort 专用 known_hosts。
- 删除或撤销后重写托管配置。

Review：

1. `[P1]` 主配置中的 Include 在不再有任何托管连接时不会移除。安全上问题不大，但应在设置中显示“已安装/空配置”状态并提供修复或卸载。
2. `[P1]` 备份没有保留策略，长期操作会积累文件。
3. `[P2]` 详情只显示“已同步”，没有展示实际生效配置差异或一致性检查。

## 6. 设备栏目

### 6.1 设备列表和身份合并

设备列表合并两类来源：

- KeyPort 注册设备：有设备 ID、登记时间、最近活跃、撤销状态和同步来的公钥。
- Tailscale 节点：有 node ID、MagicDNS、IP、在线状态、系统和网络信息。

合并规则：

- 当前 Mac 固定优先展示。
- 当前 Tailscale Self 与当前 KeyPort 设备合并。
- 远程 KeyPort 设备只有在保存过稳定 Tailscale 身份后才与对应节点合并，不仅凭显示名称猜测。
- 稳定 node ID 优先，必要时可用完全匹配的 Tailscale IP 回退。
- 旧的同名本机注册记录会被抑制，减少重复。
- 未注册的 Tailscale peer 仍可作为网络设备单独展示。
- 进入设备栏目时自动刷新，工具栏也可手动刷新。
- Tailscale 未安装、未登录、未运行或输出无效时，显示明确不可用状态，不影响其他本地功能。

Review：

1. `[P1]` 一个列表混合“我的 KeyPort Mac”和“Tailnet 上的普通节点”，对象权限和可操作能力不同。建议分成“我的设备”和“网络设备”两个区段。
2. `[P2]` 没有设备搜索、在线筛选或只看有 SSH 账户的筛选。

### 6.2 设备详情

KeyPort 信息：

- 设备 ID。
- 登记时间。
- 最近活跃。
- 有效/已撤销状态。

Tailscale 信息：

- 在线或离线。
- Tailnet 名称。
- MagicDNS。
- IPv4/IPv6 地址。
- 操作系统。
- DERP 区域。
- 离线节点最近在线时间。
- 出口节点是否可用或正在使用。

密钥与访问：

- 设备拥有的同步公钥。
- 每把密钥已知授权到多少 SSH 账户。
- 设备可访问的账户列表。
- 跳转到密钥或服务器详情。

Review：

1. `[P0]` 虽然模型包含设备撤销状态，界面只有只读展示，没有“撤销设备”或“恢复设备”动作，也没有编排远端公钥清理。
2. `[P1]` 没有重命名设备功能；设置中也缺少需求提出的默认设备名称。
3. `[P2]` KeyPort“最近活跃”主要随当前设备 Tailscale 状态刷新而更新，不等同于稳定的应用活跃或 SSH 使用时间，文案需要更精确。

### 6.3 Tailscale SSH 管理

对非当前、可路由的 Tailscale 节点：

- MagicDNS 优先作为建议主机；没有 DNS 时优先 IPv4，再回退其他地址。
- 建议服务器名称、`Tailscale` 分组、22 端口和账号级别名。
- 识别已经管理的 SSH 账户。
- 识别 SSH Config 中存在但尚未加入 KeyPort 的账户。
- 展示账户别名、本机授权状态和本机密码是否可用。
- 可查看、编辑、添加账户。
- 在线时可以用已有密码直接授权。
- 没有密码时可以进入“输入密码并授权”流程。
- Tailscale 建议会约束主机必须仍属于目标节点，防止编辑到无关地址。

Review：

1. `[P1]` 服务器账户管理在设备栏目重复实现了一套“查看、编辑、授权、输入密码并授权”，与服务器栏目行为容易漂移。建议设备页只展示关联和快捷跳转，或统一使用完全相同的共享动作组件。
2. `[P2]` 离线时全部编辑也被禁用，即使用户只想修改本地名称或别名。应按“需要网络”和“纯元数据”拆分禁用条件。

### 6.4 当前设备批量授权

- 显示当前设备本地密钥数量。
- 统计状态为“需要授权”或“等待同步”的服务器数量。
- 没有密钥时自动生成一把 Ed25519。
- 整批操作只请求一次 Touch ID 或 Mac 登录密码。
- 按顺序处理每个待授权账户。
- 单项失败不会终止后续账户。
- 单项结果写入审计日志。

Review：

1. `[P0]` 界面没有逐服务器的进行中、成功、失败、跳过和原因反馈；失败只留在审计日志中，未达到新设备授权向导要求。
2. `[P0]` Host Key 异常、缺少密码等需要用户介入的项目不会暂停并引导处理，只会失败后继续。
3. `[P1]` “授权待处理服务器”在待处理数量为 0 时仍可点击，只要存在任意活动服务器，可能要求一次身份验证后什么也不做。
4. `[P1]` 当前串行处理，符合避免限流的安全取向，但没有取消、重试失败项或结果摘要。

## 7. 审计日志栏目

### 7.1 当前记录内容

最多保留 1000 条本地事件，覆盖：

- 应用状态加载。
- 服务器创建、更新、删除、复制别名和复制主机。
- 密钥扫描、生成、导入和加载到 Agent。
- Host Key 确认、轮换、待确认和不匹配阻断。
- 密码与密钥 SSH 检查。
- 公钥安装、批量授权单项、读取远端授权和撤销。
- SSH Config 写入和从 SSH Config 导入服务器。
- Keychain 密码保存和存储策略变更。
- CloudKit 同步。
- 加密归档导入和导出。
- 机器配置刷新。

每条事件模型包含：时间、分类、动作、稳定目标 ID、结果和 info/warning/error 级别。

隐私边界：

- 不记录密码。
- 不记录私钥或私钥路径。
- 不记录 SSH 原始输出。
- 不记录可恢复秘密的命令数据。
- 审计日志不进入 CloudKit，也不进入加密元数据归档。

### 7.2 当前界面

- 列表只显示动作、当天时间、分类和结果。
- 右侧概览显示保留条数和隐私说明。
- 提供“清除日志”按钮。
- 没有事件详情选择。

Review：

1. `[P1]` 模型已有目标 ID 和严重级别，界面完全没有展示，难以回答“哪个账户失败、为什么失败”。
2. `[P1]` 没有按日期、分类、级别、目标或结果搜索和筛选。
3. `[P1]` 没有导出诊断日志；需求设置中提出的日志导出尚未实现。
4. `[P1]` 清除全部日志没有确认，清除动作本身也不会形成审计事件。
5. `[P2]` 列表只显示时间不显示日期，跨天记录难以识别。
6. `[P2]` `change-password-storage`、`tailscale-enrollment`、`account-authorization` 等部分动作或结果没有中文映射，会回退显示英文原值。
7. `[P2]` 复制操作追加审计事件后不会立即持久化，应用随后异常退出时可能丢失该条记录。

## 8. 设置栏目

设置使用系统 Settings 场景，分为“通用、同步、安全性、归档”四个标签。

### 8.1 通用

当前提供：

- 当前设备名称，只读。
- 当前设备 ID，只读。
- 托管 SSH Config 路径。
- KeyPort known_hosts 路径。

Review：

1. `[P1]` 没有修改设备名称。
2. `[P1]` 没有选择默认密钥，当前默认候选受最近密钥选择影响。
3. `[P1]` 没有检测或修复 SSH 文件权限、Include 安装状态和配置一致性的入口。

### 8.2 同步

元数据同步：

- 开关控制 CloudKit 私有数据库同步。
- 显示关闭、检查中、同步中、成功、ad-hoc 签名、未启用 CloudKit、未登录和失败状态。
- 显示详细原因和上次成功时间。
- 提供“立即同步”。
- 本地每次重要持久化后会以约 1 秒防抖自动同步。
- 网络、服务暂不可用和冲突支持短重试及最长约 5 分钟的指数退避。

同步的数据：

- 服务器连接、别名和共享字段。
- 当前确认的 Host Key。
- 机器配置。
- 设备和稳定 Tailscale 身份。
- 公钥元数据。
- 授权关系和删除标记。

不进入 CloudKit 的数据：

- 服务器密码。
- 私钥内容和本地路径。
- SSH Agent 状态和本地可用状态。
- 当前设备标记。
- 本地检测状态和检测详情。
- 服务器自由文本备注。
- 审计日志。

密码同步：

- 提供“新密码默认使用 iCloud Keychain”。
- 只有真实团队签名、正确 application identifier 和 Keychain access group 时才允许开启。
- ad-hoc 构建自动禁用该选项。
- 每个服务器密码仍可在编辑器中单独覆盖策略。

Review：

1. `[P1]` CloudKit 当前把整个元数据快照存成单一记录。冲突时会重新读取和重试，但同一服务器的并发编辑采用整记录版本胜出，不是需求中的字段级合并，也没有用户冲突选择界面。
2. `[P1]` 同步状态只在设置中完整展示；全局工具栏没有成功时间或失败标记。
3. `[P1]` 正式 CloudKit、iCloud Keychain 和双 Mac 联调仍缺少真实环境验收，不能仅凭代码路径认定 M2 已完成。
4. `[P2]` 关闭同步只改变本机开关，不提供删除云端元数据或退出设备的选项。

### 8.3 安全性

当前提供：

- 说明访问密码和批量授权需要 Touch ID 或 Mac 登录密码。
- 配置敏感剪贴板内容在 10 到 120 秒后清除，默认 30 秒。

Review：

1. `[P0]` 剪贴板超时设置当前没有调用方：应用没有复制密码功能，复制别名和主机又没有传入清理时间。该设置目前是无效 UI，应删除，或在真正提供敏感复制时完整接入。
2. `[P0]` 文案称“访问密码需要本地身份验证”，但新建 Keychain 项目的读取路径没有统一显式验证，需统一安全策略和实现。
3. `[P2]` 没有显示本机是否支持 Touch ID、当前实际使用的验证策略或最近失败原因。

### 8.4 加密归档

- SecureField 输入恢复密码。
- 可选择导出 `.keyport` 文件或导入现有归档。
- 使用 PBKDF2-HMAC-SHA256，默认 210,000 次迭代。
- 使用 AES-GCM 认证加密，错误密码或文件被修改都会失败。
- 容器包含格式名、版本、KDF、迭代次数、盐和密文。
- 输出使用原子写入、完整文件保护和 `0600` 权限。
- 包含服务器、备注、别名、公钥、设备和授权元数据。
- 排除私钥路径、Agent 状态、本地可用状态、当前设备标记和审计日志。
- 导入按服务器稳定 ID、设备 ID、公钥指纹和授权稳定 ID 合并。
- tombstone 和较高逻辑版本优先，避免旧归档复活已撤销授权。

Review：

1. `[P0]` 导入前没有摘要、重复项提示或确认，选中文件并通过密码验证后会直接合并到现有状态。
2. `[P1]` 导入/导出没有进入独立忙碌状态，可能与同步或其他操作并发；界面虽然参考 `model.isBusy`，归档方法本身没有设置它。
3. `[P1]` 成功后恢复密码不会自动清空。
4. `[P1]` 导入后没有立即刷新 SSH Config、known_hosts 或本地密钥扫描，只更新元数据；用户需要后续检查/同步才能完成本机落地。
5. `[P2]` 文件选择器允许通用 data 类型，没有专用 UTType 或扩展名严格校验。

## 9. 菜单栏工具

已实现：

- 应用在菜单栏显示 KeyPort 模板图标，资源不可用时回退到系统钥匙图标。
- 加载时显示“正在加载”。
- 没有可显示服务时显示“暂无已授权服务”。
- 已授权账户按服务器分组字段分区。
- 每行显示 SSH 别名和 `host[:port]`。
- 点击整行只复制纯 SSH 别名。
- 复制后图标短暂变成勾选，1.5 秒后恢复。
- 提供“打开 KeyPort”和“退出 KeyPort”。

Review：

1. `[P0]` 菜单栏先过滤掉分组为空的账户，再按分组展示，因此所有未分组的已授权账户都会消失。应增加“未分组”区或按服务器名称分组。
2. `[P1]` 分组名称来自自由文本，大小写或首尾空格标准化不足时可能形成看似重复的区段。
3. `[P1]` 当前只提供复制别名，没有“在主窗口中打开此账户”或复制完整 `ssh <alias>` 的上下文菜单。
4. `[P2]` 菜单栏复制会写审计日志但不立即持久化。

## 10. 端到端流程盘点

### 10.1 全新服务器首次授权

`添加服务器 -> 填资料和密码 -> 扫描 Host Key -> 人工确认 -> 密码 SSH 验证 -> 保存 -> 生成/选择本机密钥 -> 授权此 Mac -> 写远端 authorized_keys -> 密钥 SSH 复验 -> 生成 SSH Config -> 外部执行 ssh <alias>`

结论：代码路径基本闭环。真实 Linux/OpenSSH 远端、不同算法和异常中断仍需要环境验收。

### 10.2 已有 SSH Config 连接纳管

`扫描主配置别名 -> ssh -G 解析 -> 添加到服务器 -> 输入密码 -> 确认 Host Key -> 验证 -> 授权`

结论：发现和导入已实现，但导入后密码弹窗缺少 Host Key 确认入口，流程当前断成多次手工跳转。

### 10.3 新 Mac 恢复

`启用 CloudKit -> 合并服务器/公钥/授权元数据 -> 恢复 iCloud Keychain 密码 -> 创建本机设备和密钥 -> 状态降级为待本机检查 -> 一次本地身份验证 -> 批量授权 -> 写本机 SSH Config`

结论：底层路径基本存在；逐项进度、需介入项暂停、结果摘要和双 Mac 真实联调尚未闭环。

### 10.4 Host Key 变化

`任何认证前重新扫描 -> 对比算法和指纹 -> 变化则阻断 -> 并排显示旧/新指纹 -> 用户明确确认 -> 写 known_hosts -> 记录轮换事件 -> 重试原操作`

结论：阻断逻辑已实现；历史指纹保存和可追溯证据不足。

### 10.5 撤销某台设备

`当前可登录设备读取 authorized_keys -> 识别 KeyPort 公钥 -> 选择目标 -> 本地身份验证 -> 再验 Host Key -> 精确删除 blob -> 远端复验 -> tombstone 同步`

结论：单把密钥撤销已实现；设备级一键撤销、跨服务器执行结果和失败重试未实现。

### 10.6 离线与云服务不可用

- CloudKit 关闭、未登录或网络失败时，本地状态和现有 SSH Config 继续工作。
- iCloud Keychain 不可用时可以保存本机 Keychain 项目。
- Tailscale 不可用不阻止手工服务器管理。

结论：降级边界合理。

## 11. 重复功能与建议归属

| 重复能力 | 当前入口 | 问题 | 建议唯一归属 |
| --- | --- | --- | --- |
| 添加/编辑 SSH 账户 | 服务器、密钥导入、设备 Tailscale | 三种流程的 Host Key 与密码处理不一致 | 服务器栏目持有统一账户向导，其他栏目只发起带预填参数的同一流程 |
| 授权当前 Mac | 服务器工具栏、服务器详情、密钥详情、设备详情 | 禁用条件、自动生成密钥和反馈不一致 | 共享 `AuthorizationAction` 状态机，各入口只改变上下文 |
| 密码输入与验证 | 服务器编辑器、独立密码弹窗、Tailscale 保存并授权 | Host Key 确认和同步默认值不一致 | 一个凭据验证步骤组件 |
| Host Key 确认 | 服务器编辑器内联、独立确认弹窗 | 旧/新指纹展示不同 | 一个统一确认界面与事务 |
| SSH 连接展示 | 服务器列表、密钥“SSH 连接”、设备“SSH 管理” | 用户不清楚哪个才是主记录 | 服务器是账户真源；密钥和设备只展示关联和跳转 |
| 同步动作 | 全局工具栏、设置“立即同步” | 全局入口缺状态，设置入口信息完整 | 保留两处，但共享同一状态控件和错误反馈 |
| 复制别名 | 服务器列表、服务器详情、命令菜单、菜单栏 | 成功反馈不一致 | 共享复制组件和 accessibility announcement |
| 机器/系统信息 | 服务器列表、服务器详情、设备 Tailscale | 来源和更新时间不同 | 明确标注“SSH 采集”与“Tailscale 报告”，避免混为一类 |

建议的信息架构原则：

- “服务器”只回答：我有哪些 SSH 账户，当前 Mac 能否安全登录，下一步做什么。
- “密钥”只回答：这台 Mac 和其他设备有哪些身份密钥，它们是否可用、关联到哪里。
- “设备”只回答：哪些设备属于我、哪些网络节点可发现、各设备拥有哪些密钥和访问权。
- “审计日志”只回答：谁在何时对哪个对象做了什么，结果是什么。
- “设置”只管理全局策略，不承载日常对象操作。

## 12. 需求覆盖判断

### 12.1 基本完成

- 服务器和多账户增删改查、搜索与端点聚合。
- Host Key 首次确认、变化阻断和严格 known_hosts。
- Ed25519 生成、Ed25519/RSA 导入、公钥指纹和 Agent 扫描。
- 密码安全传给 OpenSSH，不进入命令参数。
- 公钥查重、备份、原子写入和复验。
- 单账户免密验证、授权读取和单把公钥撤销。
- 独立 SSH Config、幂等 Include 和用户配置保护。
- 本地结构化审计日志。
- CloudKit 敏感字段清洗、授权 tombstone 和自动重试。
- AES-GCM 加密元数据归档。
- Tailscale 节点发现和 SSH 账户建议。

### 12.2 部分完成

- 新 Mac 批量授权：底层执行存在，向导和逐项反馈不完整。
- 多设备同步：代码路径存在，缺少真实双 Mac 联调和字段级冲突处理。
- 密钥可用性检查：能扫描，但失效文件和 Agent-only 状态不准确。
- 密码安全策略：存储边界正确，但读取前本地身份验证不统一。
- Host Key 历史：能识别并确认轮换，但旧指纹不长期保留。
- SSH Config 导入：能发现和建立元数据，但首次确认向导断裂。
- 日志诊断：事件丰富，但 UI 不展示目标、级别和详情。
- 设置：主要开关存在，默认设备名、默认密钥、日志导出等缺失。

### 12.3 当前未提供

- 删除已保存服务器密码。
- 安全删除或移除本地密钥。
- 私钥口令完整支持。
- 设备重命名、设备撤销/恢复和跨服务器设备级撤销。
- 批量检测 UI。
- 批量授权逐项进度、暂停、取消、结果和重试。
- Host Key 可查看历史。
- 导入归档前摘要和冲突确认。
- 审计日志筛选、详情和导出。
- 显式默认密钥设置。
- 正式签名、公证发行包及真实 CloudKit Production 验收。

### 12.4 明确非目标

- 内置终端和任意命令执行。
- 团队共享、审批和企业 SSO。
- 堡垒机、SSH CA、自定义集中式 AuthorizedKeysFile。
- Windows、Linux、iOS 和 iPadOS 客户端。
- 通用基础设施监控。

## 14. 验证边界

当前仓库已有核心解析、命名、Host Key 评估、认证参数、CloudKit 清洗/合并、授权 tombstone、SSH Config、Tailscale 解析、归档加密和密码校验门控检查。Keychain 还有独立 XCTest。

仍不能只凭本地自动检查确认的部分：

- 真实 Linux/OpenSSH 密码认证和远端原子更新。
- Ed25519/RSA、加密私钥和不同服务器策略组合。
- 两台 Mac 之间的 CloudKit 与 iCloud Keychain 恢复。
- Developer ID 签名、公证和 CloudKit Production schema。
- 全部窗口尺寸、深色模式、VoiceOver、Full Keyboard Access 和边界状态截图。

因此更准确的产品结论是：M1 的主要代码闭环已经形成，M2 的底层同步与批量授权路径已经存在；要称为“可发布的一期完成版”，仍需先完成 P0 流程修复、安全策略对齐和真实环境验收。
