# SSH KeyPort 一期需求规格

- 文档版本：V1.1
- 产品阶段：MVP
- 目标平台：macOS
- 文档状态：需求基线

## 1. 产品愿景

SSH KeyPort 是一款 macOS 原生 SSH 免密授权管理应用。

它帮助用户完成服务器录入、主机身份确认、本机密钥发现或创建、公钥授权、SSH Config 生成和多台 Mac 的独立授权。完成配置后，终端、脚本和未来的 AI 工具只需使用稳定的 SSH 别名连接服务器，无需接触服务器密码或私钥内容。

KeyPort 不提供内置终端、交互式 SSH 会话或命令执行工作台。它只负责管理连接入口、设备密钥、服务器免密授权、授权状态和安全恢复流程。实际 SSH 使用仍由 Terminal、脚本或其他外部工具通过别名完成。

## 2. 一期核心原则

1. 每台 Mac 使用独立的公私钥对。
2. 私钥只保存在生成它的 Mac 上，不通过 CloudKit 或 iCloud Keychain 同步。
3. 同一服务器连接在所有 Mac 上使用相同 SSH 别名。
4. 服务器密码只允许保存在 macOS Keychain；开启同步时使用 iCloud Keychain，不进入 CloudKit。
5. 新 Mac 通过同步服务器资料和密码、生成本机密钥并重新注入公钥，实现近似无感恢复。
6. 公钥指纹是密钥唯一性的最终判断依据。
7. KeyPort 不覆盖用户已有 SSH 配置，不修改或删除未知公钥。
8. Host Key 未确认或发生异常时，禁止自动连接和授权。
9. 状态检测是免密授权管理的辅助能力，不作为独立监控产品建设。

## 3. 一期目标与完成标准

### 3.1 目标

| 编号 | 目标 | 验收结果 |
| --- | --- | --- |
| G01 | 降低 SSH 免密配置成本 | 用户无需手工执行密钥生成、复制或配置命令 |
| G02 | 统一服务器入口 | 同一连接在不同 Mac 上使用相同 SSH 别名 |
| G03 | 保持设备独立 | 每台 Mac 拥有可独立识别和撤销的密钥 |
| G04 | 识别已有免密 | 自动发现本机可用于目标服务器的密钥 |
| G05 | 安全完成授权 | 使用服务器密码一次性安装本机公钥 |
| G06 | 支持多 Mac 恢复 | 新 Mac 可近似无感地重新获得独立授权 |
| G07 | 为自动化和 AI 接入做准备 | 外部工具只依赖稳定别名，不读取秘密 |

### 3.2 一期内部里程碑

#### M1：本地闭环

1. 添加服务器连接。
2. 确认服务器 Host Key。
3. 扫描或创建本机 Ed25519 密钥。
4. 使用密码注入公钥。
5. 生成 SSH Config。
6. 使用 `ssh <别名>` 成功登录。

#### M2：多设备闭环

1. 通过 CloudKit 同步服务器资料、别名、公钥和授权元数据。
2. 通过 iCloud Keychain 可选同步服务器密码。
3. 新 Mac 生成独立密钥。
4. 用户通过一次 Touch ID 或系统密码验证启动批量授权。
5. 新 Mac 使用与其他 Mac 相同的 SSH 别名连接服务器。
6. 任意设备密钥可以被单独识别和撤销。

M1 和 M2 均通过验收后，一期才视为完成。

## 4. 核心术语与数据模型

### 4.1 术语

| 术语 | 定义 | 示例 |
| --- | --- | --- |
| 连接名称 | KeyPort 界面中的可读名称，可修改 | Doris 生产库 |
| SSH 别名 | 用户在终端、脚本和 AI 中使用的账号级稳定入口 | `prod-doris-root` |
| 服务器端点 | 主机或域名与 SSH 端口的组合 | `192.168.1.20:22` |
| 登录账号 | 服务器上的 SSH 用户 | `root` |
| 设备名称 | 用户可读的 Mac 名称 | Jooder MacBook Pro |
| 设备 ID | KeyPort 为当前 Mac 生成的永久唯一 ID | `dev_8a3f91c2` |
| 密钥 ID | KeyPort 为一把密钥生成的永久唯一 ID | `key_6cd814e9` |
| 公钥指纹 | 由公钥计算的 OpenSSH SHA256 指纹 | `SHA256:...` |
| 授权关系 | 某台服务器允许某把设备密钥登录的关系 | Server + Key |

### 4.2 核心对象

#### ServerConnection

- 稳定记录 ID
- 连接名称
- 主机或域名
- SSH 端口
- 登录账号
- SSH 别名
- 分组与备注
- 已确认的 Host Key 集合
- 最近检测状态与时间
- 创建时间与更新时间

连接唯一性不能只按 IP 判断。至少使用稳定记录 ID管理，并以主机、端口和账号作为重复项提示依据。同一 IP 的不同端口或不同账号可以建立独立连接。

同一服务器端点可以包含多个登录账号。每个账号仍使用独立的 `ServerConnection` 记录、密码、SSH 别名和授权状态；界面按服务器端点聚合这些账号。默认 SSH 别名使用“服务器别名基底 + 用户名”的形式，例如 `prod-doris-root`，用户可以为每个账号自定义别名。

#### Device

- 设备 ID
- 设备名称
- 本机标记
- 首次注册时间
- 最近活跃时间
- 撤销状态

#### SSHKey

- 密钥 ID
- 所属设备 ID
- 密钥类型
- 公钥内容
- 公钥指纹
- 私钥本地路径
- SSH Agent 状态
- 创建来源：扫描、导入或生成
- 本地可用状态

#### Authorization

- 服务器连接 ID
- 密钥 ID
- 公钥指纹
- 远端公钥备注
- 授权状态
- 首次授权时间
- 最后验证时间

#### SecretLocator

- 服务器连接 ID
- Keychain service
- Keychain account（使用稳定的服务器连接 ID）
- 是否允许 iCloud Keychain 同步
- 最后验证时间

数据库和 CloudKit 只保存用于定位 Keychain 项的非秘密标识，不保存服务器密码值，也不依赖仅在单台 Mac 有效的 opaque persistent reference。

## 5. 命名规范

### 5.1 SSH 别名

已有 SSH Config 连接默认复用原始 `Host` 别名；新建连接默认格式：

```text
<分组或环境>-<连接标识>
```

示例：

```text
prod-doris
test-redis
office-nas
```

规则：

1. 只允许小写字母、数字和连字符。
2. 不允许空格、通配符和 SSH Config 特殊字符。
3. 在 KeyPort 管理范围和用户现有 SSH Config 中必须唯一。
4. 同一地址的不同账号可追加账号，例如 `prod-doris-admin`。
5. 别名同步到所有 Mac；本机配置引用各自的设备私钥。
6. 修改别名前提示脚本、书签和 AI 引用可能失效。

### 5.2 公钥备注

统一格式：

```text
keyport:v1:<密钥ID>:<设备标识>
```

示例：

```text
keyport:v1:key_6cd814e9:jooder-macbook-pro
```

规则：

1. 密钥 ID 创建后永久不变。
2. 设备标识只用于识别和展示，不作为唯一性依据。
3. 密钥相同性以公钥指纹为准。
4. 修改设备名称时允许同步更新 KeyPort 管理的公钥备注。
5. 不修改未知来源的公钥备注。

### 5.3 本地密钥文件

建议路径：

```text
~/.ssh/keyport/
  identities/
    key_6cd814e9
    key_6cd814e9.pub
  config
  known_hosts
```

私钥目录权限为 `700`，私钥文件权限为 `600`。文件名使用密钥 ID，不使用用户可修改的设备名称。

## 6. 核心用户流程

### 6.1 首次添加服务器

1. 用户输入连接名称、主机或域名、端口、账号和 SSH 别名。
2. 用户可输入密码并选择是否保存、是否通过 iCloud Keychain 同步。
3. KeyPort 检查 DNS、网络和 SSH 端口。
4. KeyPort 获取并展示 Host Key 类型和指纹。
5. 用户确认服务器身份。
6. KeyPort 扫描本机 SSH Config、密钥文件和 SSH Agent。
7. KeyPort 按候选优先级测试可用密钥。
8. 如果已有密钥可登录，建立授权关系。
9. 如果没有可用授权，用户选择已有密钥或创建本机 Ed25519 密钥。
10. KeyPort 使用密码登录并安全注入公钥。
11. KeyPort 重新测试密钥登录。
12. 只有公钥复检成功后才生成本机 SSH Config，并将状态更新为“免密可用”。

### 6.2 新 Mac 近似无感恢复

1. 用户登录相同 Apple ID 并开启 KeyPort iCloud 同步。
2. KeyPort 从 CloudKit 恢复服务器、SSH 别名、Host Key、公钥和授权元数据。
3. KeyPort 为新 Mac 创建唯一设备 ID 和本机 Ed25519 密钥。
4. KeyPort 从 iCloud Keychain 检查可用的服务器密码。
5. 用户通过一次 Touch ID 或系统密码确认本次批量授权。
6. KeyPort 对 Host Key 与同步记录进行比较，异常时停止操作。
7. KeyPort 逐台向服务器注入新 Mac 公钥。
8. KeyPort 生成引用本机私钥的 SSH Config。
9. 公钥复检成功的连接标记为“免密可用”；失败项展示原因和重试入口。

近似无感的定义是：不重新录入服务器资料、不复制公钥、不执行 SSH 命令，仅进行一次本机身份验证。网络、密码或服务器策略异常时允许用户补充处理。

### 6.3 查看和撤销设备授权

1. KeyPort 登录服务器并读取当前账号的 `authorized_keys`。
2. 解析所有 KeyPort 公钥并计算指纹。
3. 与 CloudKit 和本机数据匹配。
4. 展示当前 Mac、其他 Mac 和仅服务器存在的授权。
5. 用户选择目标设备密钥并二次确认撤销。
6. KeyPort 只删除公钥指纹完全匹配的目标记录。
7. 修改后重新读取远端文件并验证结果。

## 7. 功能需求

### 7.1 服务器管理（P0）

- 添加、编辑和删除服务器连接。
- 按名称、地址、账号和分组搜索。
- 测试网络、端口、密码和密钥登录。
- 显示 Host Key、授权状态和最后检测时间。
- 展示并复制稳定的 SSH 别名。
- 支持批量状态检测，并限制并发数。
- 删除连接时不得删除仍被其他连接使用的密钥。
- SSH 账户边界是“端点主机 + 端口 + SSH 用户”；设备是否关联不能替代账户级免密复检。
- 设备与已管理 SSH 账户只按 Tailscale MagicDNS 或 Tailscale IP 精确匹配；不做端口探测、反向 DNS、网段推断，也不把 Telnet 记录推断为 SSH 服务。
- 公网 IPv4 与 Tailscale IP 没有 Tailscale node ID、云实例/机器稳定 ID 或用户明确确认时，必须保持未匹配，不能自动合并。

### 7.2 密钥管理（P0）

- 扫描 `~/.ssh/config`、`~/.ssh/*.pub`、KeyPort 目录和 `ssh-add -L`。
- 识别 Ed25519 和常见 RSA OpenSSH 密钥。
- 导入已有 OpenSSH 私钥。
- 生成 Ed25519 密钥。
- 计算并展示 SHA256 公钥指纹。
- 查看和复制公钥。
- 检查私钥文件权限、格式和 SSH Agent 状态。
- 将本机私钥加载到 SSH Agent。
- 删除密钥前展示服务器关联和远端授权风险。

扫描到只有公钥或只有 Agent 身份时，不得假设存在可导出的本地私钥。

### 7.3 公钥注入与撤销（P0/P1）

- 使用密码时不得通过进程命令参数传递秘密。
- 创建远端 `~/.ssh` 和 `authorized_keys` 时设置安全权限。
- 注入前按公钥指纹查重。
- 保留 `authorized_keys` 中未知公钥和未知选项。
- 修改前创建权限受控的远端备份。
- 使用临时文件和原子替换，避免写入中断损坏原文件。
- 注入和撤销后必须重新读取并验证。
- 一期只支持用户有权直接修改自己 `authorized_keys` 的常见 Linux OpenSSH 环境。
- 自定义 `AuthorizedKeysFile`、集中目录、SSH CA 和堡垒机暂缓。

### 7.4 SSH Config 管理（P0）

KeyPort 生成独立配置文件：

```sshconfig
Host prod-doris
    HostName 192.168.1.20
    Port 22
    User root
    IdentityFile ~/.ssh/keyport/identities/key_6cd814e9
    IdentitiesOnly yes
    UserKnownHostsFile ~/.ssh/keyport/known_hosts
```

主 `~/.ssh/config` 只维护一条受控 Include：

```sshconfig
Include ~/.ssh/keyport/config
```

要求：

- 写入前备份主配置。
- 检测已有 Include，操作必须幂等。
- 检测用户已有 Host 别名冲突。
- 不重写用户已有 Host 配置段。
- 删除连接时只修改 KeyPort 专用配置。
- 明确定义 Include 插入位置，避免被已有 `Host *` 意外覆盖。

### 7.5 Host Key 管理（P0）

- 首次连接必须展示 Host Key 类型和 SHA256 指纹。
- 用户确认后保存到 KeyPort 专用 `known_hosts`。
- 同一端点可以记录多个 Host Key 算法。
- Host Key 变化时停止密码和密钥认证。
- 展示新旧指纹、算法、首次确认时间和最近使用时间。
- 用户明确确认后才能接受轮换，并保留历史审计记录。
- `ssh-keyscan` 获取的指纹只代表当前网络返回结果，不应描述为已被可信第三方验证。

### 7.6 密码与 Keychain（P0/P1）

- 密码默认掩码显示。
- 查看或复制密码前进行 Touch ID 或系统密码验证。
- 剪贴板中的密码按设定时间自动清除。
- 服务器密码只保存为 Keychain 项目。
- 用户可为每个连接控制是否保存和是否允许 iCloud Keychain 同步。
- CloudKit、数据库、SSH Config、日志和命令参数不得出现密码。
- 授权成功后允许用户删除保存的密码。
- 本机私钥口令使用设备本地 Keychain 项目，不参与同步。

### 7.7 CloudKit 与多设备同步（P1）

CloudKit 同步：

- 服务器连接和 SSH 别名。
- 已确认 Host Key 及其历史。
- Device、SSHKey 的公钥元数据和 Authorization。
- 删除标记和数据版本。

CloudKit 禁止同步：

- 私钥内容。
- 私钥口令。
- 服务器密码。
- 默认操作日志。

同步要求：

- iCloud 不可用时本地 SSH 功能继续工作。
- 展示同步状态、最后同步时间和错误。
- 删除记录使用删除标记，避免离线旧设备恢复数据。
- 自动合并不同字段的非冲突修改；同一字段并发修改时提示用户选择。
- 设备撤销状态应同步到其他设备，但远端公钥删除仍需拥有服务器访问权限的设备执行。

### 7.8 加密导入导出（P1）

- 支持导出服务器资料、公钥和授权元数据。
- 默认不包含服务器密码和本机私钥。
- 可选私钥导出仅用于原设备备份或灾难恢复，不作为新增 Mac 的默认注册方式。
- 包含秘密时要求二次确认和恢复密码。
- 文件使用带版本的加密容器、认证加密和完整性校验。
- 导入前展示摘要，导入失败不得修改现有数据。
- 服务器按稳定记录 ID 合并，并以主机、端口和账号提示潜在重复；密钥按公钥指纹去重。

### 7.9 操作日志（P0）

记录：

- 服务器和密钥的创建、修改、删除。
- Host Key 确认和变化。
- 密码、密钥登录检测的结果类型。
- 公钥注入、撤销和验证结果。
- SSH Config 修改。
- CloudKit 和 Keychain 同步结果。
- 导入导出结果。

禁止记录密码、私钥、私钥口令、完整敏感命令输出或可复原秘密的数据。

### 7.10 授权状态检测（辅助功能）

- 在服务器列表工具栏提供“检测”按钮。
- 支持检测选中服务器，并可选支持批量检测。
- 检测 DNS、TCP 端口、Host Key、当前设备公钥认证和 SSH Config 一致性。
- 公钥认证成功后立即结束，不启动交互式 Shell，不执行用户命令。
- 公钥认证失败且具备本地密钥与 Keychain 服务器密码时，使用“同步 SSH 授权”主流程，先通过本机身份验证，再安装当前 Mac 公钥并复检；没有可用密码时保留“待授权”状态并引导添加密码。
- 结果直接更新服务器列表状态列、最后检测时间和详情中的错误原因。
- Host Key 异常属于阻断级事件，不继续认证。
- 一期不建设独立监控页面、定时后台任务、菜单栏摘要或通知系统。

## 8. 状态模型

| 状态 | 含义 | 主要操作 |
| --- | --- | --- |
| 免密可用 | 同一端点、端口和 SSH 用户的公钥复检成功 | 重新检查、复制别名 |
| 检查中 | 正在扫描 Host Key 或验证当前 Mac 公钥 | 等待当前检查完成 |
| 待授权 | 当前 Mac 有密钥但服务器未授权 | 同步 SSH 授权、添加并验证密码 |
| 同步中 | 正在安装公钥或执行授权后复检 | 等待授权同步完成 |
| 缺少本地密钥 | 同步记录存在，但当前 Mac 没有对应可用私钥 | 创建或选择本机密钥 |
| 指纹待确认 | 首次连接，Host Key 未确认 | 查看并确认 |
| 指纹异常 | Host Key 与已确认记录不一致 | 停止连接、人工核对 |
| 无法连接 | DNS、网络或端口异常 | 重试、编辑连接 |
| 密码认证失败 | 密码错误或服务器不允许密码认证 | 更新密码、查看详情 |
| 密钥认证失败 | 候选密钥均无法登录 | 重新授权、查看详情 |
| 授权冲突 | 密钥 ID、指纹或远端记录不一致 | 停止自动修改、人工处理 |
| 待检查 | 同步记录需要在当前 Mac 重新检查 | 重新检查、同步 SSH 授权 |

只有在本地、同步记录或可读取的远端记录提供证据时，才能展示“缺少本地密钥”；不能仅凭一次登录失败推断该状态。

## 9. 页面与桌面交互

### 9.1 主窗口

- 使用原生侧边栏与详情布局。
- 侧边栏包含服务器、密钥、设备和日志。
- 服务器列表按端点聚合 SSH 账号；多个账号时先展示服务器名称、地址和用户数，再列出各账号、SSH 别名和当前 Mac 授权状态。
- 服务器只有一个账号时使用一行紧凑展示服务器、地址、用户名、SSH 别名和授权状态，不重复渲染服务器标题与账号行；复制别名、检查和授权操作仍直接作用于该账号。
- 详情页先展示 SSH 账户身份、免密状态和“同步 SSH 授权”主按钮，再展示公钥复检结果、Host Key/密码/本地密钥阻断原因、设备关联证据和机器配置；SSH 别名等资料放在后面。
- 设备关联明确展示精确匹配依据；未匹配时说明仅支持 Tailscale MagicDNS/IP，不自动推断 Telnet 或公网 IPv4。
- 机器配置同步、SSH 授权同步和 CloudKit 元数据同步是三个独立操作；机器配置失败不得覆盖“免密可用”。
- 核心操作同时提供工具栏、右键菜单和键盘入口。
- 服务器列表工具栏提供检测按钮，检测结果回写现有状态列。

### 9.2 添加服务器

- 基础连接信息与高级配置分层展示。
- 新增服务器时同时录入首个 SSH 用户；已有服务器可以继续添加用户。
- SSH 别名默认按“服务器别名基底 + 用户名”生成并允许编辑。
- 密码保存和 iCloud Keychain 同步使用独立开关。
- 连接测试按 DNS、端口、Host Key、认证阶段展示进度。
- 保存与授权失败时保留用户已填写信息。

### 9.3 新设备授权向导

- 展示待授权服务器数量和预计操作。
- 一次本机身份验证后执行批量授权。
- 每台服务器独立展示成功、失败和跳过状态。
- Host Key 异常、密码失效等高风险或需输入场景必须单独暂停处理。

### 9.4 设置

- CloudKit 同步设置。
- 服务器密码 iCloud Keychain 同步策略。
- Touch ID 与剪贴板清理策略。
- 默认设备名称和默认密钥。
- SSH Config 与已知主机文件位置。
- 导入导出。
- 日志查看、导出和清理。

## 10. 安全要求

1. 服务器密码持久化只允许进入 Keychain。
2. 私钥使用标准 OpenSSH 加密格式或等价的设备本地保护。
3. 私钥、私钥口令和服务器密码不得进入 CloudKit。
4. 敏感数据不得写入日志、数据库、配置文件或命令参数。
5. 密码读取、复制和批量设备授权前必须进行本机身份验证。
6. Host Key 异常时禁止继续认证和公钥修改。
7. 所有远端文件修改必须查重、备份、原子写入并验证。
8. 所有用户输入在传给进程或远端命令前必须作为结构化参数处理，禁止拼接未经转义的 Shell 命令。
9. 一期不提供远程命令执行接口；未来 AI 或 CLI 只能获取别名、授权状态和非秘密元数据，不提供密码或私钥读取接口。
10. 应用退出、任务取消和错误路径应尽快释放内存中的敏感数据。
11. 安全日志记录操作主体、目标、阶段和结果，但不记录秘密。

## 11. 非功能要求

| 类别 | 要求 |
| --- | --- |
| 性能 | 单连接在网络正常且候选密钥有限时，目标 5 秒内给出首个明确状态 |
| 并发 | 批量检测和授权限制并发，避免触发服务器限流 |
| 可用性 | CloudKit 或 iCloud Keychain 不可用时，本机已有 SSH 连接继续工作 |
| 兼容性 | 一期支持具有常规用户主目录和 OpenSSH `authorized_keys` 的 Linux 服务器 |
| 可恢复性 | 本地和远端关键文件修改前备份，写入失败保持原文件可用 |
| 可诊断性 | 错误包含阶段、原因、目标和可执行建议 |
| 可升级性 | 数据模型、导出文件和公钥备注均包含版本信息 |
| 无障碍 | 支持键盘导航、VoiceOver、减少动态效果和高对比度 |

## 12. 一期暂缓范围

- Windows、Linux、iPhone 和 iPad 客户端。
- 团队共享、成员管理和多用户审批。
- Web 管理后台与企业 SSO。
- 堡垒机、跳板机完整支持。
- SSH CA、SSH 证书和动态临时凭据。
- 自定义或集中式 `AuthorizedKeysFile`。
- AI 或 KeyPort 自动执行用户命令。
- 高风险命令审批系统。
- 通用服务器资源与业务监控，例如 CPU、内存、磁盘、进程、端口服务和业务指标。
- 旧 Mac 在线审批新 Mac 的可信设备注册流程。

## 14. 待技术验证事项

以下事项不改变产品目标，但必须在实现前通过技术原型确认：

1. 应用采用直接分发并公证，还是进入 Mac App Store；沙盒策略会影响 `~/.ssh` 和系统进程访问。
2. 密码认证和远端文件修改采用嵌入式 SSH 客户端库，还是受控系统 SSH 进程。
3. iCloud Keychain 同步项目与 Touch ID 交互的具体访问控制实现。
4. 标准 OpenSSH 私钥口令、Keychain 和 SSH Agent 的协作方式。
5. SSH Config Include 的安全插入位置和不同用户配置的兼容性。
6. CloudKit 删除标记、设备撤销和字段级冲突合并策略。
