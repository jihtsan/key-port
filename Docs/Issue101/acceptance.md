# Issue #101：含空格的 known_hosts 路径修复

## 原因与范围

AccessPilot 的独立根目录含 `Application Support`。OpenSSHService 传参虽使用独立 argv 元素，但 `-o UserKnownHostsFile=...` 的值仍会按 OpenSSH 配置语法解析成文件列表。原来的未加引号值被拆分，导致已经确认并持久化的主机指纹无法在实际 SSH 握手中使用。

已为路径值加双引号并处理转义、百分号与非法换行；不修改任何主机信任记录，不关闭严格检查。FirstAccessFlow 只接受明确实现安全错误信息协议的服务错误，失败页展示本地分类原因，未知原始错误不直接输出。带具体服务原因的登录失败不再一律引导修改密码。

## 验证

- 实际故障页面为第一步账户验证失败；应用已保存的主机指纹与用户此前提供的新指纹一致。
- 对用户已指定端点执行禁用全部凭据认证的严格校验：原参数报 Host key verification failed；仅为路径加引号后到达预期的 Permission denied。没有发送密码、私钥，也没有更改 known_hosts。
- 新回归测试直接调用 OpenSSHService，使用含空格的临时目录复制已信任记录，由注入执行器强制禁用密码、公钥及交互认证。修复前同测试失败，修复后通过。此测试通过环境变量显式启用；一般 CI 没有已批准的目标/信任记录时跳过。
- 定向检查通过：AccessPilot 10 项、实际 OpenSSH 主机校验回归 1 项、Interface 38 项。新增安全错误信息测试验证显示已分类原因、重试清空与不显示原始未知错误。
- Red/green 测试摘要见同目录日志。构建与签名校验通过后重新启动原验收 App 路径。
