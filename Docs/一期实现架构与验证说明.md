# SSH KeyPort 一期实现架构与验证说明

> **文档定位（2026-08-28）：** 本文描述早期 MVP 的实现基线，未覆盖之后合入的 Host v6、CloudKit v2、服务发现与隧道承重层。当前承重契约见 [主机工作台技术架构](./Design/JODER-10/host-workbench-architecture.md)，Graph 改版见 [Graph 拓扑与跨设备授权架构](./Graph拓扑与跨设备授权架构.md) 和 [整体重构与迁移计划](./整体重构与迁移计划.md)。

## 工程与场景

- 最低系统：macOS 14。
- 工具链：Swift 6.3.3；当前机器仅安装 Command Line Tools，没有完整 Xcode。
- 工程形态：SwiftPM SwiftUI GUI 应用，`script/build_and_run.sh` 组装标准 `.app` bundle。
- 场景：`WindowGroup("SSH KeyPort", id: "main")`、三栏 `NavigationSplitView`、独立 `Settings`。
- 状态所有权：根场景持有 Observation `AppModel`；SSH、Keychain、CloudKit、文件与归档操作由 Actor 服务隔离。
- AppKit 边界：应用激活、SwiftPM bundle 首窗兜底、剪贴板和系统文件面板。SwiftUI 仍持有视图和业务状态。

## 数据边界

- 本地非秘密状态保存在版本化 JSON 快照中，目录和文件权限分别为 `0700`、`0600`。
- 选择 JSON Actor Store 是因为当前环境缺少完整 Xcode 和 SwiftData 模型/迁移工具；存储接口独立，可在 Xcode 工程落地后替换为 SwiftData，不影响服务与界面。
- 服务器密码只进入 Security.framework Keychain。同步开关映射到 synchronizable Keychain item；运行时仅在签名包含 `keychain-access-groups` 时开放，避免 ad-hoc 构建返回 `errSecMissingEntitlement` 后阻断本机保存。
- 私钥只存在本机 OpenSSH 文件，不进入快照、CloudKit 或归档。
- CloudKit 上传前剥离本地路径、Agent 状态、当前设备标记、检测状态和审计日志。
- `.keyport` 归档使用 PBKDF2-HMAC-SHA256（210,000 次）派生密钥及 AES-GCM 认证加密。

## SSH 边界

- 系统 OpenSSH 封装只暴露 Host Key 扫描、公钥认证、固定授权文件维护、授权读取和撤销。
- 密码由主应用在 LocalAuthentication 成功后从 Keychain 读取，并通过随机 `0600` FIFO 交给 AskPass helper。
- 所有认证显式使用 KeyPort 专用 `known_hosts` 和严格 Host Key 校验。
- `authorized_keys` 写入前备份，按公钥 blob 去重，经同目录临时文件原子替换后再次验证。
- SSH Config 只生成 `~/.ssh/keyport/config`，主配置只在所有 Host 段之前加入一条幂等 Include。

## 当前验证条件

- Debug 和 Release 构建、警告即错误构建均通过。
- 核心回归检查和 AskPass FIFO 集成检查通过。
- `.app` 可启动；CoreGraphics 确认主窗口在屏幕上且具有非零尺寸。
- 本地 ad-hoc 签名完整性通过，本机 Keychain 保存可用；Developer ID、Keychain Sharing、iCloud entitlement 与公证需要真实团队证书。ad-hoc 构建会禁用 iCloud Keychain 同步选项。
- 当前没有可用的隔离 Linux SSH 服务器和双 Mac iCloud 账户，因此真实密码认证、远端原子写入、算法矩阵、CloudKit 冲突与 iCloud Keychain 跨设备同步仍需外部环境验收。
