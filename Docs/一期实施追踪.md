## 当前事实源与兼容层

| 主题 | 当前实现 | 一期处理口径 |
| --- | --- | --- |
| 展示与拓扑事实 | `TopologySnapshot` 是 Graph 与统一拓扑的事实源；`TopologyStore` 保存本地拓扑 | 继续复用，不创建第二套 Graph/路由事实源 |
| SSH 兼容投影 | `AppSnapshot`、`ServerConnection` 和 `SSHCompatProjection` 仍承载旧 SSH/Keychain 适配 | 逐步将新流程接到拓扑事实；保留可回滚的兼容投影，直到迁移门槛满足 |
| 账户与路径 | `SSHAccount` 归属于 Node；`SSHConnectionProfile` 引用账户并保存别名与 `SSHRoutePolicy` | 授权继续账户级；路径扩展为固定端点或有序允许候选端点 |
| 当前路径策略 | `SSHRoutePolicy` 只有 `automatic(networkScope:)` 与 `fixed(endpointID:)`；Planner 会按本机观测、`Endpoint.priority` 和稳定 ID 排序 | `automatic` 的旧语义保持兼容；新增候选顺序必须是显式、可迁移的数据，不把既有排序冒充用户排序 |
| TCP 地址选择 | `AddressSelectionCoordinator` 已有固定不自动回退、并发探测、整体预算、WaitingForUser 与网络 epoch，但 `AddressSelectionV2Gate.defaultEnabled` 为关闭 | 先接入真实 SSH 计划与辅助脚本；保留固定策略和“接通后不切换”门禁 |
| SSH 配置 | `SSHConfigService` 原子生成 `~/.ssh/keyport/config`，并幂等加入 `Include ~/.ssh/keyport/config`；已有用户配置不整体覆盖 | 继续保护用户 `~/.ssh/config`、现有别名和受限权限；新增脚本配置与生成状态必须可诊断、可修复 |
| 身份与授权 | `HostKeyService`、`OpenSSHService`、`TrustedSSHSession` 使用系统 `/usr/bin/ssh`；Keychain、AskPass FIFO、公钥安装/读取/精确撤销已存在 | 不内嵌 SSH、不让辅助脚本读取密码；多地址只复用已确认的账户授权，不重复安装公钥 |
| 同步与迁移 | `TopologyCloudMetadataSnapshotPolicy` 清洗本地观测、私钥路径和本机状态；Host v6 CloudKit v2/authority/shadow migration 仍是恢复契约 | 同步 profile、端点和授权元数据时沿用显式 allow-list、冲突、版本、墓碑和本地恢复规则 |
| 隧道承重能力 | `KeyPortTunnelBroker`、`TunnelRegistry` 和既有 C4 回归仍在仓库中 | 不因一期导航整合删除；服务隧道暂不扩展为一期主流程 |

## 旧数据、别名与生成文件迁移

| 旧对象/能力 | 新一期归属 | 兼容约束 |
| --- | --- | --- |
| `AppSnapshot.servers[].id` | `SSHConnectionProfile.id` | 保留 profile ID，避免 Keychain、授权和审计目标漂移 |
| `ServerConnection.name/group/notes` | `Node.name/group/notes` | 同一 Node 下多个账户/端点共享机器信息，不按用户名或公网 IP 自动合并 |
| `ServerConnection.host/port` | `Endpoint.address/port/protocol/networkScope` | 旧记录迁移为一个固定端点；端口不同仍可能是不同机器，必须有稳定身份或人工确认 |
| `ServerConnection.username` | `SSHAccount.username` | 账户稳定身份为 `(Node, normalized username)`；同一账户可被多个 profile 引用 |
| `ServerConnection.alias` | `SSHConnectionProfile.sshAlias` | 原有命令继续有效；固定策略不会因升级自动变为候选回退 |
| 旧 `Authorization` | `SSHAuthorization(accountID, keyID, fingerprint)` | 共享授权事实归账户；`AccessVerification` 仅记录某设备最近一次验证 |
| `ServerConnection.status/keyCheck/lastCheckedAt` | 当前设备的 `AccessVerification` | 不把云端同步成功或远端授权存在伪装成本机可登录 |
| `~/.ssh/keyport/config` | 本机生成的 OpenSSH 配置 | 原子写入、`0600`、冲突 fail closed；用户 `~/.ssh/config` 只做幂等 Include |
| `~/.ssh/keyport/known_hosts` | 本机端点 Host Key 信任材料 | 每个候选端点独立核对映射；不关闭 `StrictHostKeyChecking`，不盲目信任扫描结果 |
| `~/.ssh/keyport/identities/` | 当前设备本地密钥 | 私钥不进入 CloudKit、归档或脚本配置；每台 Mac 独立生成/持有 |
| 旧 Servers/Keys/Devices/Logs 页面 | 服务器、我的设备、活动、设置 | 迁移每个独有能力后再退役重复入口；不删除用户数据、安全门禁或审计记录 |

## 状态语义锁定

一期的三个状态轴必须独立显示，不能用一个“已同步”或“在线”概括：

1. **配置同步**：profile、端点、别名及非敏感工作区资料是否已与 iCloud 合并；另外显示本机 SSH 派生配置/辅助脚本是否存在且与当前事实一致。
2. **授权事实**：指定 `SSHAccount` 是否接受指定 `WorkspaceDeviceProfile` 的 `SSHKey`，由账户级 `SSHAuthorization` 的远端状态表达。它不表示当前网络可达，也不表示本机最近登录成功。
3. **最近验证**：当前设备依照具体 `SSHConnectionProfile + Endpoint` 的 `AccessVerification`，必须带设备、时间、端点、传输方式和结果；其他设备只能显示最近已知资料，不冒充实时状态。

`ReachabilityObservation` 另行表示有时间和网络 epoch 的本机 TCP 可达性。主机身份信任、远端授权、可达性和最近验证互不替代。
