# 统一 SSH 连接策略：使用与验收

## 使用

1. 选择服务器，打开 **连接策略与地址顺序**。
2. 勾选该别名参与连接的地址，调整顺序及各自端口。
3. 选择 **固定第一条地址** 或 **按顺序自动回退**。
4. 保存策略；需要验证其他地址时使用 **保存并验证所选地址**。

日常命令始终是：

```sh
ssh home-server
```

普通“在终端打开”和“复制连接命令”按整个策略执行。点击地址只改变查看/验证对象；**复制此地址诊断命令** 才生成固定端点的 `ssh -F …` 命令。

- 新建多地址连接默认建议顺序回退。旧固定记录保持原连接方式，明确保存策略时才升级。
- 未经本机验证的地址保留在候选中，但不进入执行清单。修改端口产生待验证的新端点，不沿用旧端口证据。
- 地址共用账户授权，批量验证使用现有密钥，不重复安装公钥。首次信任仍需在连接设置中确认。
- 仅 DNS/TCP 连接失败会尝试下一条；一旦接通 TCP，主机身份、认证、会话失败都交给 OpenSSH，不重新选址。
- 已建立的会话不因本机编辑或撤销而自动断开。

## 本机安装与恢复

应用把签名的 `KeyPortSSHRelay` 复制到用户 SSH 目录中的稳定路径。自动策略通过受管理 Include 引用不可变 manifest 和 known_hosts；固定策略直接使用严格 OpenSSH 配置。源应用关闭或移动不影响已安装的命令。

“SSH 连接”菜单提供 **测试连接策略**、**同步终端别名** 和 **修复连接策略组件**。修复会保存损坏的生成文件，再重新安装；用户对 SSH Include/config 的外部修改会作为冲突提示，不会被强行覆盖。

普通编辑先准备依赖；安装失败保留上一代，并显示“策略已保存，终端仍使用上一代配置”。撤销、身份变化或候选权限收窄先写入待恢复的工作区记录，再使旧依赖失效。启动时优先恢复该记录，避免旧配置被重新启用。

最近 TCP 选址记录包含尝试 ID、配置代次、profile、端点、阶段和时间，每个策略只保留最新一条。它不代表 SSH 登录成功。

## 旧资料与同步

- 同账户、同别名的旧固定 profile 显式合并为一个策略；不同账户/别名不自动合并。
- 原 `path-*.conf` 在端点仍有效且验证有效时保留为诊断入口，包含 canonical 原始 ID；其主机信任也绑定同一节点身份。
- 版本 2 工作区阻止旧应用继续写入。云端使用 `keyport-topology-policy-v1` 记录，首次从 `keyport-topology-v1` 读取旧资料，之后旧客户端对旧记录的写入不会覆盖新版策略。其他 Mac 需要升级后同步。
- 同版本并发修改顺序会保留完整的一方并标出冲突，暂停执行，等待用户确认；不会把两份顺序拼成新顺序。
- 本机私钥路径和验证证据不会从云端复制为另一台 Mac 的可用状态。

## 验收证据

### 已验证

- 核心模型：逐端点证据、重复升级、旧记录重放、并发顺序收敛、禁止旧写入者降级。
- 工作区：普通命令一致、候选过滤、固定/自动切换、端口变化、删除、撤销、旧诊断 ID、安装失败保留上一代、撤销中断后的重启恢复。
- 安装：签名与版本验证、权限与安全读取、损坏 helper/manifest 修复、外部 Include 冲突与事务回滚。
- 系统 OpenSSH：解析实际安装的配置；真实本地 sshd 完成连接前回退、两个并发连接、删除源应用后连接，以及已认证会话在生成配置撤下后继续运行。隔离测试用 `-F` 选择临时用户配置，并非端点专用配置。
- 真实本地 sshd 验证主机密钥错误和登录失败不会尝试备用地址；IPv4/IPv6 字节转发和 DNS 截止时间通过独立测试。
- 原生应用：实际显示三条地址，固定/自动切换、候选勾选、上下排序与端口输入可操作。界面验收未保存用户的策略草稿。
- 打包：`./script/build_and_run.sh --verify` 打包、签名并启动带 relay helper 的应用。

### 尚未进行的实机验收

当前应用为 ad-hoc 签名，无法进行真实 CloudKit 同步。两台 Mac 的签名版本同步、实际 LAN/Tailnet 网络切换和电脑重启后的终端连接仍需专门实机验收。本地跨设备数据测试和移除源应用的 SSH 测试不替代这些结论。
