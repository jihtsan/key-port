# 统一 SSH 策略实施记录

## P1：模型与迁移基础（#131）

- profile 可记录显式策略版本与被归并的 profile ID；旧数据缺字段可解码。
- 同账户、同别名归并，其他账户/别名不受影响；端点与授权事实不删除。
- 验证记录 ID 增加 endpointID，避免一个策略的不同地址互相覆盖。
- 云端合并保留 superseded 元数据，旧 fixed 记录不会重新作为有效入口出现。
- 调整规划中的 canonical 选择：采用组内稳定最小 ID，不采用各 Mac 的本地默认 ID，避免两台 Mac 同时升级选出不同 canonical；候选顺序仍由用户明确指定。
- 本阶段只提供纯迁移能力，正式工作区将在 P4 接入。

## P2：策略执行基础（#132）

- 编译仅放行同 Node、主机指纹一致、具备本机账户授权及当前端点绑定验证的候选。
- 新增结构化 Relay SSH 配置，不接受任意 ProxyCommand 文本。
- DNS 在可终止子进程中完成，解析与拨号共用预算；IPv4/IPv6 共用候选截止时间。
- 清单通过 O_NOFOLLOW 打开后 fstat 检查，读取期间限制字节数。
- Relay 只记录最近 TCP 选址，带独立 attemptID，不声明登录成功。
- 定向测试和真实本地 OpenSSH fixture 通过：HostKeyAlias、首选不可达回退、身份错误和认证失败停止；DNS 阻塞子进程有界回收。

## P3：本机配置代次

- 应用构建同时打包并签名 KeyPortSSHRelay。安装器验证其代码签名，复制到用户 SSH 目录下按内容哈希命名的稳定路径。
- manifest 与 known_hosts 按内容组成不可变代次，先完成依赖准备再通过现有 Include 日志事务激活。重复准备复用文件，篡改会停止激活。
- 严格配置只接受结构化 relay 命令；原有任意 ProxyCommand 仍被拒绝。
- 验证：11 个安装器测试通过，包括不可变代次、篡改、事务回滚与真实 ssh -G；git diff --check 通过。应用整体验收在 P5。

## P4：工作区与界面接线

- 新增地址归属于同账号同别名的一个策略；候选逐条投影，验证证据绑定地址、端口、主机密钥、本机密钥及用户名。
- 日常按钮统一执行 ssh 别名；指定地址 -F 命令只在明确的诊断操作中生成。固定策略和顺序回退均可编辑，批量验证复用账户密钥，不重复安装授权。
- 旧固定记录通过显式策略保存升级，保留候选验证与 superseded 诊断路径兼容。删除固定地址不会擅自选新地址，需重新保存固定策略。
- 安全失效先停用旧依赖；普通修改先准备新代次，再持久化并激活。成功后清理旧代次，安全失效失败不会继续使用旧策略；元数据同步的别名冲突保留记录但不导出冲突别名。
- 工作区版本 2 防止旧客户端覆盖新版工作区。授权管理按用户选中/偏好策略选路，缺少唯一策略或验证证据时停止。
- 验证：完整 script/test.sh 通过；后续补充的工作区、授权、配置解析回归通过。自动策略测试读取实际生成的 manifest，并以 ssh -G 验证别名作用域、候选过滤与普通命令；本地 sshd 覆盖连接前回退和认证失败停止。

## P5：集成验收、恢复与旧版本隔离

- 为普通编辑与安全失效分别处理安装失败：普通编辑保留上一代；撤销先保存可恢复的安全变更并失效旧依赖，重启优先恢复，不能因 Include 回滚恢复旧授权。
- 旧 canonical ID 的诊断命令也保留原端点；每个诊断入口使用节点身份固定的独立 known_hosts。
- helper 检查版本与签名、提供显式修复；记录最新 TCP 选址及代次。策略编辑支持勾选、排序、独立端口与验证。
- OpenSSH 的 banner 等待覆盖 relay 的完整 20 秒预算，再保留 5 秒握手时间，避免原先 5 秒等待提前打断回退。
- 并发策略排序冲突暂停执行；CloudKit 新记录首次读取旧资料后独立更新，阻止旧客户端丢弃新字段。此记录切换无需新增 CloudKit record type。
- 本机真实 OpenSSH 使用实际安装的配置通过并发连接、源应用移除及已建立会话保持测试。故障注入覆盖普通回滚、安全变更中断与重启恢复。
- 原生策略界面已实际检查；构建、签名、启动通过。真实两台 Mac 的 CloudKit/LAN/Tailnet 与电脑重启验收未完成，详见 [使用与验收](使用与验收.md)。
