# 首次访问状态与适配边界

Refs #92，依赖 #90 / 草稿 PR #91。此实现只由 KeyPortDesignPreview 启动；生产 KeyPort 不链接 KeyPortInterface。

## 状态、事件、结果

| 当前状态 | 事件/实际适配结果 | 下一状态与副作用 |
|---|---|---|
| 单表单 | 提交无效 | 留在表单，保留输入供纠正；不调用适配器 |
| 单表单 | 提交有效 | 保存非敏感草稿；本次密码暂存到登录完成/失败/取消；检查主机 |
| 检查主机 | 不可达 | 不可达失败；未登录、未授权 |
| 检查主机 | 身份不匹配 | 阻断失败；无忽略/继续按钮，重试事件也不能绕过 |
| 检查主机 | 可信身份 | 连续面板第 1 步登录 |
| 检查主机 | 首次待确认 | 显示地址、ED25519、完整占位指纹、确认/取消 |
| 首次待确认 | 已核对，继续 | 适配器确认成功后进入登录；确认失败停止 |
| 主机检查/确认/登录 | 取消或 Escape | 返回原表单；保留名称、地址、端口、账户、别名、认证模式；清空密码 |
| 第 1 步登录 | 登录失败 | 账户验证失败；不会开始授权 |
| 第 1 步登录 | 成功 | 清空密码；第 2 步先查询设备+服务器身份+账户的公钥授权 |
| 第 2 步核对 | 已存在 | 跳过安装；第 3 步免密验证 |
| 第 2 步核对 | 缺失 | 开始幂等授权；操作开始即将结果标为未知 |
| 第 2 步核对 | 未知 | 停止，要求核对；不猜测缺失并安装 |
| 第 2 步安装 | 实际完成 | 标记已授权；第 3 步验证 |
| 第 2 步安装 | 失败/结果未知 | 显示授权失败/待核对；不承诺未写入，不宣称免密成功 |
| 第 2 步授权 | 停止后续步骤/Escape | 取消页；保留未知结果，不承诺远端回滚 |
| 第 3 步验证 | 失败 | 已授权但验证未通过；部分成功 |
| 第 3 步验证 | 停止后续步骤/Escape | 取消页，明确授权仍存在，免密未验证 |
| 第 3 步验证 | 实际通过 | 成功页，明确模拟范围 |
| 失败/取消 | 修改/返回表单 | 原表单非敏感输入与认证方式保留；密码为空，无自动必填错误 |
| 失败/取消 | 重新验证（密码模式） | 返回同一表单重新输入密码；不能复用已清理密码 |
| 失败/取消 | 重新验证（密钥模式） | 重新检查主机、登录、授权现状；已存在公钥跳过安装 |
| 任意旧请求 | 取消/新请求之后迟到 | generation + Task cancellation 检查丢弃；不能刷新页面或启动下一步 |
| 成功 | 在终端打开 | 同页显示请求中；实际适配结果决定成功/终端不可用 |
| 成功 | 复制命令 | 同页显示复制中；实际适配结果决定已复制/复制失败 |
| 终端不可用/复制失败 | 重试/复制/选择文本 | 保留成功配置状态，提供恢复操作；不会重新授权 |
| 成功 | 返回服务器/Escape | 关闭预览面板，取消未完成交接；迟到交接不会显示成功 |

主机确认没有 Return 默认确认，避免用户在未核对身份时误按回车。Cmd+J 是预览专用“模拟完成当前步骤”，不是生产控制。

## 可复现入口

打开预览 App → 添加服务器（或 Cmd+N）→ 右下角“模拟场景”。选择后提交一次表单。首次主机确认仅出现在未信任 fixture；确认后同一面板保持在当前待完成步骤，点击“模拟完成”或 Cmd+J 才让模拟适配器回调。

| 模拟场景 | 操作与预期 |
|---|---|
| 首次连接成功 | 提交→主机确认→依次模拟完成登录/授权/验证→成功 |
| 已信任主机 | 提交直接进入登录，无重复主机确认 |
| 已授权账户／新增地址 | 修改地址再提交；完成登录后直接验证，不出现安装等待 |
| 地址不可达 | 提交直接失败；修改地址入口保留非敏感输入 |
| 主机身份不匹配 | 提交阻断；无忽略/重新验证按钮 |
| 登录失败 | 完成登录模拟后失败；无授权等待 |
| 授权失败（未写入） | 完成登录、授权模拟后失败；UI 保守标记未知，重试会查询 |
| 已授权但验证失败 | 完成三步后部分成功；改模拟场景为成功再重试，跳过重复安装 |
| 授权结果未知 | 模拟写入后返回未知错误；改成功后重试，查询到已存在并跳过安装 |
| 终端不可用 | 流程成功→在终端打开→模拟完成交接→错误；可复制/重试 |
| 复制失败 | 成功→终端反馈→复制命令→模拟完成复制→失败；改成功后重试 |
| 各步取消 | 在相应待完成进度按 Escape；登录返回表单，授权/验证进入取消页 |

可在同一面板中修改模拟场景，以验证恢复。场景选择仅改变 fixture 结果，不是真实服务器状态。重新打开面板重置 fixture；同一面板的重试保留内存主机信任和授权账本。

## 适配契约及后续迁移

- `FirstAccessAdapter` 是可替换接口；`FirstAccessFlow` 只等待真实返回，不含 sleep/timer 或默认成功。
- `FixtureAccessAdapter` 仅在预览 executable 内。手动 continuation 驱动；不调用 SSH、Process、剪贴板、钥匙串、CloudKit、磁盘写入。已复制/终端反馈明确模拟。
- 授权键为 deviceID + verified serverID + account。地址只是 inspect/login/verify 的连接参数，不能当作 serverID。未来适配器必须完成可信身份映射，不能把未知指纹自动视作已知服务器。
- 真实 authorize 必须以账户公钥指纹执行幂等核对/安装；遇到取消或不确定结果，下次必须重新查实。generation 防 UI 迟到不等于远端事务回滚。
- 真实 adapter 必须在 cancel 时释放凭据/session；不将密码保留到任务闭包之外，不记录凭据。Swift String 清空不构成内存安全擦除的证明。
- 终端适配器需负责命令/别名实际可用、安全转义与 OpenSSH 交接；成功仅证明交接动作完成，不证明 SSH 会话连通。预览别名未安装，命令只作展示。
- 本阶段删除新主页“校验成功”占位弹窗，替换为连续流程；生产旧 UI、AppModel 和 SSH 授权流程保留到真实接入 Issue，沿用 #90 文件矩阵，迁移后必须删除被替代旧入口。Graph、本机配置同步和生产迁移未实现。
