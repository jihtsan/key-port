# KeyPort 一期产品边界与功能整合规划

- 整理日期：2026-09-11
- 关联 Issue：[#62](https://github.com/jihtsan/key-port/issues/62)
- 状态：产品方向与整合规划；本次仅归档文档，未实施功能删除或新增能力。
- 证据范围：当前源码与本轮产品讨论。原生应用窗口读取失败，清单不构成视觉、键盘或无障碍验收。

## 1. 产品定位与优先级

KeyPort 是基于本机 OpenSSH 的 SSH 免密授权与跨 Mac 配置管理应用。通过可视化界面组织服务器、账户、地址、别名和各台 Mac 的授权，编排接入、验证、撤销及配置生成，并通过 iCloud 同步跨设备所需资料。

第一层：完成免密授权与 iCloud 跨 Mac 接入；Tailscale、多地址与 Graph 为这条主线服务。

第二层：在第一层闭环后增加跳板免密登录。

一期主线：导入服务器 → 整理账户与地址 → 建立本机免密 → 通过固定别名连接 → 其他 Mac 同步接入。

本文定义本期产品范围和交互目标。旧文档中的通用网络拓扑、VPN/RDP、服务扩展方向不再自动构成本期交付要求；底层身份模型、安全、数据迁移和恢复契约仍需保留并逐项验证。本文不表示现有领域模型已经重写。

## 2. 已确认的应用边界

| 组件 | 职责 | 不承担的职责 |
| --- | --- | --- |
| KeyPort 主应用 | 可视化管理；调用本机 SSH 工具完成主机身份确认、公钥安装、验证、撤销；管理密钥引用；同步资料；生成本地配置与辅助脚本 | 自行实现 SSH 协议、内置交互终端、通用网络路由、常驻代理连接 |
| 通用辅助脚本及配置 | 根据别名对应的候选地址与顺序，执行有界的连接前尝试，接通后转发数据 | 密码读取、授权修改、配置修改、SSH 认证重试、会话迁移 |
| 本地 OpenSSH | SSH 主机身份校验、密钥认证、加密传输和会话 | KeyPort 产品资料管理和 iCloud 同步 |
| Tailscale | 提供网络连接与可供发现的地址信息 | 替代目标 SSH 账户的授权事实 |

用户继续使用 `ssh <别名>`。主应用退出后，生成的配置和辅助脚本仍应独立工作，无需额外安装完整 CLI；但脚本及其调用工具仍是运行时依赖，必须纳入安装、更新、依赖检查与修复。

脚本是否调用系统工具、具体工具可用性与版本兼容，需在实现时验证。不能仅因文件是 Shell 脚本就宣称零依赖。脚本保持通用，服务器地址与顺序放在配置中，不为每台服务器复制一套逻辑。

“高级可视化逻辑”指数据组织、步骤编排、状态解释、诊断与配置生成。主应用可以主动调用 SSH 执行用户请求的授权维护，但日常 SSH 会话不依赖主应用运行。

## 3. 账户、地址与别名模型

| 对象 | 含义 |
| --- | --- |
| 服务器 | 具有稳定身份的目标机器，可复用现有 Node 模型 |
| SSH 账户 | 服务器上的用户名；凭据和公钥授权归属于该账户 |
| 访问地址 | 主机名或 IP、端口、协议和网络类型；同一服务器可有多个 |
| 连接入口 | 一个别名引用一个账户与一项路径策略 |
| 路径策略 | 固定地址，或用户允许使用的候选地址与顺序 |
| 免密授权 | 某台 Mac 的密钥被目标服务器账户接受 |

一个别名 → 一个服务器账户 → 一组候选地址或一个固定地址。

确认多个地址指向同一目标账户及授权配置后，增加地址无需重复创建账户或安装公钥；需要验证新路径。相同用户名、相似名称或同一个公网出口不足以自动证明是同一服务器。不同端口可能指向不同机器。

自动策略只处理连接前的地址不可达；接通并交给 OpenSSH 后，身份校验失败、认证失败或会话断开均不得被解释为继续尝试地址的许可。TCP 接通不等于 SSH 登录成功。主机信任如何映射到候选端点必须单独设计验证，不得通过关闭校验解决多地址问题。

跨 Mac 暂沿用当前每台 Mac 独立私钥、不共享私钥的方案。iCloud 同步服务器、账户、公钥及授权元数据、别名和路径意图；密码是否通过 iCloud Keychain 同步由用户选择。每台 Mac 本地生成配置并使用自己的密钥和本地路径。本机网络观测、最近连接结果不能冒充其他设备的实时状态。

## 4. 删除、合并与下沉清单

P0：一期核心闭环；P1：本期界面整合；P2：后续优化。

| 编号 | 当前问题 | 处理方式 | 优先级 |
| --- | --- | --- | --- |
| D1 | 节点与全部节点并存，后者主要重置筛选 | 合并为服务器入口，全部作为列表筛选 | P1 |
| D2 | SSH 账户独立导航与节点详情重叠 | 迁入账户编辑、授权读取和撤销等独有功能，再移除独立导航 | P1 |
| D3 | 活动与审计日志读取同一批审计事件，文案不一致 | 合并为活动，提供进行中、失败、全部记录筛选与审计详情 | P1 |
| D4 | 密钥页面混合 SSH 连接、服务器密码和本地密钥 | 连接导入移到导入服务器；密钥放入我的设备与高级管理 | P1 |
| D5 | 设备混合工作区 Mac 与 Tailscale 发现节点 | 我的设备展示参与同步授权的 Mac；发现节点移到服务器发现与关联流程 | P1 |
| D6 | 顶部、列表、右侧检查器重复操作 | 保留主要操作区，检查器按需打开显示高级详情 | P1 |

| D8 | Test Case、V6 Shadow、兼容适配器等工程词进入产品 | 改为关联服务器、只读原因等用户可理解文案；技术详情放诊断区 | P1 |

## 5. 保留与优化清单

| 编号 | 改进目标 | 验收标准 | 优先级 |
| --- | --- | --- | --- |
| O1 | 导入、身份确认、密钥准备、授权和配置生成形成连续流程 | 不跳转多个一级栏目即可完成首次免密；失败保留已完成步骤 | P0 |
| O2 | 同一服务器下统一管理多个地址 | 新增 Tailscale 地址不重复创建账户或授权；不确定关联需确认 | P0 |
| O3 | 连接配置支持固定/自动策略、候选地址勾选及排序 | 一个别名可尝试多个地址；固定模式不自行换地址 | P0 |
| O4 | 修正路径选择器将手选地址也显示为自动的问题 | 分开表达策略、手动选择和最近实际路径 | P0 |
| O5 | 通用辅助脚本与配置的完整交付 | 主应用退出后可连接；首选不可达可尝试备用；有超时、诊断、依赖检查和修复 | P0 |
| O6 | 我的设备突出新 Mac 接入 | 同步后明确已有资料、缺少的本机授权和下一步 | P0 |
| O7 | 分离配置同步、授权、最近验证状态 | 同步成功不等于本机可登录；验证附带时间与实际路径 | P0 |
| O8 | 批量授权支持目标选择、逐项进度与恢复 | 显示成功/失败/待处理，只重试失败项，不影响成功项使用 | P0 |
| O9 | 主操作随状态变化 | 按需显示启用免密、验证免密或在终端打开；编辑配置作为次级操作 | P1 |
| O10 | Graph 聚焦当前 Mac 的授权关系与待办 | 可追溯到账户和密钥；选中后查看路径与验证时间；不把在线等同授权 | P1 |
| O11 | 保留旧别名与固定入口 | 原有命令改版后不失效；用户主动选择升级自动策略 | P0 |

当前已有固定/自动策略模型，但这不等于本次讨论的有序候选地址与独立脚本已经实现。上述验收项均需实际测试，不能以枚举类型、配置生成成功或进程启动代替。

必须保留：独立设备密钥、主机身份确认、精确公钥撤销、账户与地址分离、日志与秘密隔离、现有 SSH 配置保护、数据迁移恢复能力。

## 6. 一期目标信息架构

| 入口 | 主要任务 |
| --- | --- |
| 服务器 | 列表/Graph、导入、账户、地址、别名、各 Mac 授权 |
| 我的设备 | 设备密钥、同步状态、授权覆盖、新设备接入 |
| 活动 | 任务进度、失败恢复、历史和审计详情 |
| 设置 | iCloud、安全、脚本与配置状态、归档和高级选项 |

服务器详情首屏：当前账户、常用别名、本机免密状态、下一步操作。随后是地址策略与其他设备授权；机器信息、指纹明细和诊断按需展开。Graph 与列表共用同一套事实与操作，不能形成第二套管理逻辑。

## 7. 暂缓范围

| 能力 | 处理 |
| --- | --- |
| 跳板免密、多跳 | 第二层，在直连与跨设备流程验收后推进 |
| 服务管理、服务隧道 | 暂停扩展，从默认主流程移开；已有实现先检查依赖与使用，再决定退役 |
| VPN/RDP 等多协议工作台 | 不进入一期主导航与接入流程 |
| 自动网络拓扑、路由控制、无缝会话迁移 | 不属于一期及辅助脚本职责 |
| 持续机器性能监控 | 不扩展；已有机器资料作为辅助信息保留 |

## 8. 实施顺序与验收

1. 修正自动路径文案与状态语义，锁定旧别名兼容规则。
2. 完成 P0：地址策略、独立脚本与配置、首次授权、新 Mac 接入与失败恢复。
3. 迁入旧页面独有功能，再合并导航、操作区与退役页面。
4. 整理 Graph、详情层级与文案，补充实际界面、键盘操作和无障碍检查。

每个实现阶段单独关联 Issue、独立分支和 PR，运行与范围相称的验证。迁移前列清旧数据、别名和生成文件映射；不得静默删除用户自有配置或密钥。

### 核心验收场景

- Mac A 导入服务器 A 的 deploy 账户，关联两个确认过身份的地址。
- 完成本机免密，生成一个别名；退出 KeyPort 后仍能运行 `ssh <别名>`。
- 首选地址连接前不可达时，在有界时间内尝试备用地址；能够解释实际路径和失败结果。
- 固定模式不换地址；主机身份异常、认证失败停止；会话断开不自动迁移。
- Mac B 同步配置后显示本机待授权，使用独立密钥完成授权和验证，并生成本地配置。
- 两台 Mac 使用相同别名，可依据各自网络选择不同地址；同步成功不伪装成本机验证成功。
- 分别查看两台 Mac 的授权，精确撤销其中一台，另一台仍可使用。
- 升级后原有别名和用户 SSH 配置仍有效；辅助脚本缺失或依赖不可用时可诊断和修复。

两台 Mac 的真实 iCloud、签名及 Keychain 环境是跨设备验收前提；离线测试不能替代真实联调。
