# 分离 SSH 账户、连接配置与账户级授权

KeyPort 将 Node 上由用户名标识的 `SSH Account` 与用户可保存的 `SSH Connection Profile` 分离：连接配置通过自定义且全局唯一的 `SSH Alias` 引用账户和访问路径策略，运行时再解析为一次性的 `Connection Plan`。`SSH Authorization` 继续只表达设备密钥被 SSH Account 接受，因此同一账户经 Tailnet、局域网、公网或多个别名访问时不会重复安装公钥；实际 Endpoint、传输方式和网络环境只进入 Host Key Trust 与 Access Verification。

## 考虑过的方案

- **网络 + 用户各自成为一份授权**：交互直观，但同一个 `authorized_keys` 账户会出现重复授权、撤销和同步冲突。
- **账户只保存一个首选地址和别名**：模型较小，但无法表达同一账户的多个稳定 SSH Alias，也会把当前设备的动态路由偏好同步给其他设备。
- **账户级授权 + 多连接配置 + 临时连接计划**：采用此方案；用户仍然在启用免密时选择账户和路径，而事实归属保持独立。

## 后果

旧的账户记录需要拆分出连接配置，旧授权按 Node 与用户名归并到账户；兼容 SSH 投影可以为同一账户生成多个 `Host` 条目，但密码、公钥授权和撤销必须以账户 ID 为准。自动命名只提供可编辑建议，别名保存后不会因地址、网络范围或用户名变化而静默重命名。
